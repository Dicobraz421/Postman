# ADR 0011. Договор платформенной функции — одно поведение на Windows, macOS и Linux

Статус: **принято** (класс B; владелец согласовал в чате 2026-11-12, порядок — решение 2026-10-26).
Основание — аудит `docs/tasks/PAR-AUDIT.md`: 48 расхождений одной функции между ОС. Платформы делались разными
волнами без общего договора; пример — stderr воркера: на Windows в никуда, на macOS в файл без предела, на Linux
наследуется при `RLIMIT_FSIZE = 0`.

## Решение
Для любой функции, реализованной на нескольких ОС (код под `sys/`, `#[cfg(windows|target_os = "macos"|…)]`),
договор один, реализация — своя. Одинаковы:

1. **Отказ.** Одно решение для всех ОС: ошибка (`Result`, «закрыто») или запасной путь («открыто»), и какой именно.
   Для безопасности и чужих данных — закрыто: отказ механизма ОС не понижает защиту молча (ни повтором в слабом режиме,
   ни `let _ = …`). Пользователь видит одно и то же: строку в окне или тост, одна причина — один ключ Fluent.
2. **Журнал.** Одно событие — один уровень по `pets: crates/pets-shell/LOGGING.md` (ERROR — функция не работает,
   WARN — работает с потерей/запасным путём, INFO — смена состояния, DEBUG — детали ОС: коды, флаги). Текст
   по-английски; без паролей, содержимого писем и внутренних имён (принципалы, узлы — только DEBUG и без секретов).
3. **Пределы и права.** Одна величина под одним именем (память, время, файлы, дескрипторы): если ОС меряет иначе,
   число пересчитывается так, чтобы один вход проходил или падал одинаково. Права — не шире самой строгой ОС:
   наследуемые дескрипторы, окружение, сеть, файлы, дампы памяти.
4. **Данные на диске.** Один перечень: что лежит (база, журнал, `open/`, кэш), где (каталог по правилам ОС —
   `paths.rs`), с какими правами (только владелец), что удаляется вместе с профилем. Секреты — никогда: только
   хранилище ОС (Credential Manager, Keychain, Secret Service); нет хранилища — вход каждый раз, не файл.
5. **Политики администратора.** Один реестр имён ключей и типов (`docs/` таблица политик, ведёт полоса политик) и одно
   чтение через `shell::policy`. Источник по ОС: Windows — `HKLM|HKCU\Software\Policies\Pets\Postman`
   (`REG_SZ` и `REG_DWORD`), macOS — профили конфигурации (управляемые настройки), Linux — файл в `/etc` (путь и
   формат — LIN-03). Значение приводится к типу реестра одинаково (bool, целое, строка, дробное → строка);
   нераспознанное — WARN и поведение «по умолчанию безопаснее».
6. **Тексты UI.** Только Fluent (`tr!`), оба языка, без названий ОС. Если действие на ОС разное (например,
   «система попросит подтвердить»), — разные ключи по смыслу, не по ОС.

Договор процесса воркера (stdin/stdout/stderr, коды выхода, пределы, уровень изоляции) — раздел «Договор процесса
воркера» в `docs/00-ARCHITECTURE.md` (пишет SBX-01); здесь не повторяется, он — частный случай этого договора.

## Отличие между ОС
Допустимо только с записанной причиной в двух местах: комментарий `// платформа: <причина>` у кода и строка таблицы
волны (ниже) с отметкой «отличие». Причина — свойство ОС (нет механизма, другой смысл API), не «так вышло». Отличие
в безопасности — ещё и ADR.

## Правило процесса
Карточка платформенной волны (`docs/tasks/<ID>.md`, затрагивает `sys/` или `cfg` по ОС) ссылается на этот ADR в
`read:` и заполняет таблицу для каждой затронутой функции. Ревью сверяет столбцы с другими ОС; пустая клетка у
реализованной ОС — волна не готова.

Шаблон:

| функция | отказ (закрыто/открыто, что видит пользователь) | журнал (уровень, событие) | пределы и права | на диске | политики (ключ, тип) | Fluent | отличие ОС и причина |
|---|---|---|---|---|---|---|---|
| | | | | | | | — |

Примеры из `PAR-AUDIT` (как должно быть по договору; имена ключей и событий — для образца):

| функция | отказ | журнал | пределы и права | на диске | политики | Fluent | отличие ОС и причина |
|---|---|---|---|---|---|---|---|
| Сбой строгой изоляции (#1, #8) | закрыто: без повтора в слабом режиме; письмо текстом, строка «песочница: …» | WARN `sandbox lockdown failed: <код>` | — | — | — | `sandbox-failed` | — |
| Политика `StorePasswords` (#3, #4) | нераспознанный тип → безопаснее (не хранить) | WARN `policy <имя>: unsupported value type` | — | — | `StorePasswords`, bool: `REG_DWORD`/`REG_SZ` · профиль bool · `/etc` bool | — | — |
| Дампы при падении воркера (#15) | закрыто: дампа нет | DEBUG код выхода | Windows WER-исключение = `RLIMIT_CORE = 0` | ничего | — | — | механизм разный, итог один |
| Права каталога данных и `open/` (#19) | ошибка установки прав → ERROR, вложение не открывается | ERROR `data dir permissions: <код>` | только владелец | `data_root`, `open/`, журнал | — | `open-failed` | Windows/macOS — наследование от профиля, Linux — `0700` явно |

Остальные строки аудита закрываются волнами из его столбца «предложение»; каждая заполняет таблицу по шаблону.
