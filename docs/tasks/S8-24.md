## Сделать
- Второй исполняемый файл крейта: `postman-viewer.exe` — та же песочница (AppContainer, Job Object 512 МиБ,
  mitigation policies с `PROHIBIT_DYNAMIC_CODE`), запуск по требованию; `wasmi` — только в нём
  (`postman-worker.exe` не растёт).
- Запрос `ViewModule { wasm, input }` → `ViewerOutput` (ABI v1 ADR 0007: `pm_abi`, `pm_alloc`, `pm_view`).
  Модуль с любым импортом — отказ до запуска; память — `StoreLimits` 256 МиБ; топливо — предел на запрос;
  сторож — 10 с; ответ — до 8 МиБ, postcard.
- Проверка ответа как чужих данных: разделы и блоки — пределы `.docx`, ссылки — проверка IR (`postman_ir`),
  картинка — ≤ 2048 px по стороне.
- Клиент в ядре — как `postman_core::render` для воркера: один процесс на сеанс, перезапуск после выхода по
  сторожу.

## Приёмка
- Тесты (модули WASM — байтами в тесте): модуль с импортом → отказ; бесконечный цикл → топливо; `memory.grow`
  сверх предела → отказ; ответ с `javascript:`-ссылкой → без ссылки; ответ 9 МиБ → отказ; песочница запускается
  (тот же `windows_probe`).
- Размеры в описании PR: `postman-viewer.exe` ≤ 2 МиБ, `postman-worker.exe` — без роста.
