## Задача
- Код договора ADR 0012 в `postman_core::channel`; реестр каналов в `Registry`; почта — канал `mail` адаптером.
- Кэш сообщений каналов в едином хранилище, миграцией (не стиранием).
- Общие функции поверх договора: список бесед всех каналов, поиск, «Медиа беседы» (MED-01), заглушить и закрепить,
  быстрый ответ и @упоминания — работают для любого канала по его возможностям.
- Канал-заглушка для тестов (в `crates/demo`): правки, реакции, «прочитано» — чтобы договор проверялся без сети.

Волны одной полосы (ADR 0012 «План по карточкам»): а — договор, хранение, демо-канал, проверки; б — адаптер почты,
список бесед, поиск, счётчики, уведомления; в — кросс-ссылки, «Переслать в…», связанные беседы, медиа, экспорт.

## CH-02а — договор, хранение, демо-канал, проверки (done)
- `postman_core::channel`: модель (адреса `postman://` в процент-кодировке, беседа, сообщение, участник, вложение,
  `ChannelFeatures` и `allows`), трейты `ChannelPlugin`/`ChannelSession`/`Flow`/`PluginStore`, события и действия,
  `ChannelError`; `Secrets` (хранилище ОС от корня, `MemorySecrets`), `LocalStore` (`local["chan/<канал>/<учётка>/…"]`).
- `channel::run`/`spawn` — поток учётки: секрет, `connect`, `catch_up(cursor)` задачей, пачки ≤ 100 мс / ≤ 500 событий
  одной транзакцией с курсором, `Gap` → история, обрыв → `Offline` и повтор `link::delay`, «печатает» в памяти 6 с,
  отказ `Unsupported` по возможностям без запроса к серверу, «Выйти».
- Хранение (`postman_cache` `channel.rs`, формат 7 без повышения): `chan_account`, `conv`, `conv_remote`, `conv_by_time`,
  `msg` (zstd от 1 КиБ), `msg_remote`, `msg_by_id`, `by_conv`, `msg_edit`, `participant`, `member` и временная
  `chan_tmp` для загрузок; запись идемпотентна по `MessageId`, правка → история, удаление без беседы, «удалить у всех» —
  строка без текста; вложения — части по SHA-256 (общие с письмами и `local`, `check_refs` их считает); «Выйти» —
  пачками по 100 000.
- `Registry::with_channel`, `channels`, `channel` (`mail` занят).
- `crates/demo` `channel.rs` — демо-канал со всеми возможностями (и урезанный `DemoServer::with_features`), сервер в
  памяти, сценарий шагов, свои часы; `channel::conformance` — 25 проверок договора и сценария; демо-канал проходит их
  (`crates/demo/tests/channel.rs`).

## CH-02б — адаптер почты, список, поиск, счётчики (done)
Два PR одной полосы по очереди: б1 — sync, адаптер почты, поиск; б2 — остальное.

### б1 — sync, адаптер почты, поиск (done, #685)
- `sync::Command::Channel { account, request }`, `sync::Event::Channel(ChanAccount, Update)`,
  `Route::Channel(ChanAccount)` (`routes_by`; `routes` и `Backend::send` её не берут), `sync::spawn_channel` —
  поток учётки с ответами в общий канал событий. `channel::spawn(plugin, Start, notify)`: `Start` — база, секреты,
  учётка, `render` (HTML → IR), `index` (поиск).
- `app-gpui/src/channels.rs`: потоки учёток из `chan_account` по реестру (живой ящик), демо-канал — в `--demo`
  (без замера и снимков); секреты — хранилище ОС (`Postman channel <канал> <учётка>`); события — `Mailer::on_channel`
  (состояние в памяти окна, интерфейса нет — CH-04); запрос — `Mailer::send_channel`.
- `channel::ConversationSource` (беседа, лента, сообщение, люди по адресу `postman://`), `Summary`, `Line`; чаты —
  `Chats` (и `list` всех бесед каналов), почта — `channel::mail::MailSource` над `thread`/`body` на лету:
  беседа `MailThread` (тема, непрочитанное, упоминания, `$muted`, `pm.pin`, S/MIME), письмо — сообщение
  (`Message-ID` без `<>`, без него `~<LetterId>`; ответ — по `References`); `MailSource::plan` — запрос канала в
  прежние команды и правки кэша («прочитано до», заглушить, закрепить, история, поиск, вложение); `mail::update` —
  события почты в `Update`; `mail::features`. Отправка почты — как сейчас, письмом.
- `Body::Html` → IR в воркере-песочнице перед записью пачки (`channel::to_ir`, `worker_render`); не вышло — HTML с
  текстом остаётся.
- Поиск: поля `channel`, `conv`, `author` (`postman_search::Scope`, `hits_in`, `delete_conversation`), документы
  `c<MsgKey>` пишет поток учётки после пачки (`channel::index::applied`), «Выйти» убирает их, пересборка — вместе с
  письмами; письма — `channel = mail`, поиск писем — только среди них. Запрос: `канал:`, `беседа:`; `от:` — все адреса
  человека (`channel::index::authors`: участники по имени, нику, почте, телефону и адреса карточки контакта).

### б2 — списки, счётчики, уведомления, очередь, IR, контакт (done)
- `channel::smart`: общий список бесед каналов (`all_chats`, закреплённые сверху) и умные папки ядра `Folder` —
  «Непрочитанное везде», «Упоминания меня», «Закреплённые», «Человек во всех каналах» — по чатам и почте
  (`mail_items`: письма всех ящиков → беседы, не больше 500); счётчики `chat_counts` (сервера при `server_unread`,
  иначе после моего «прочитано» без своих; упоминания — мой id в `mentions`), `totals` без заглушённого;
  `set_mute`/`set_pin` — действие каналу при `server_*`, иначе `local["conv/<адрес>/mute|pin"]` (предел
  `pin::LIMIT`), «Выйти» их убирает. Кто я в канале — `ChannelStore::me` (конверт учётки V2).
- `channel::notice`: уведомление по `Arrived` — не своё, не заглушённое; упоминание — «важное»; `Grouper` — одна
  беседа за 5 с — один тост.
- `chan_outbox` (`postman_cache`, добавочная таблица) и `channel::outbox`: `Request::Send { outgoing, release }` —
  строка очереди и «отправляется» в ленте (`~out<client_id>`), окно «Отменить» и «позже» держит поток таймером,
  «позже» при `scheduled_send` — сервер; `Request::Unsend`; `Update::Queued`/`Unsent`; без связи — в очередь,
  повтор с тем же `client_id`; принято — сообщение сервера вместо «отправляется»; отказ — `Step::Failed`; выход —
  `outbox::holding`/`leave` в `plugins::finish_sends`.
- IR: `Inline::Mention { id, text }` последним вариантом, `Marks::spoiler` с `serde(default)`; сообщения каналов —
  конверт V2 (строки до дополнений не разбираются и перепишутся при следующей присылке).
- `ContactCard::services`: JSContact `onlineServices` (JMAP, CardDAV через воркер), vCard `IMPP`, Exchange
  `ImAddresses`; правка карточки в «Контактах» их не снимает; `channel::index::contact_addresses`.
- `sync::Command::Channel.request` — в коробке.

## CH-02в — кросс-ссылки и общие функции
Два PR одной полосы по очереди: в1 — связи (таблицы, ссылки, связанные беседы, люди); в2 — «Переслать в…»,
«Ответить в…», медиа беседы, экспорт.

### в1 — связи (done)
- `postman_cache` `xref.rs` (добавочные таблицы, формат 7): `xref` `(цель, источник)` и `xref_from` `(источник, цель)`
  (ссылки источника заменяются целиком), `conv_link` в обе стороны, `by_message_id` `(Message-ID, LetterId)` —
  пишется в `put_body` той же транзакцией, тела до таблицы — `index_message_ids` в фоне; `person_link`
  `(канал, учётка, участник)`.
- Договор: `ChannelPlugin::link` (адрес → ссылка канала наружу) и `person_url` (ссылка на человека для карточки) —
  с ответом по умолчанию `None`; демо-канал умеет обе.
- `channel::xref`: `Links` (плагины процесса, `Links::install` в композиционном корне), цель — `mid:<id>` у письма с
  `Message-ID`, иначе `postman://`; источник — адрес сообщения, `letter:<n>`, `task:<uid>`, `event:<uid>`; ссылки
  пишут поток учётки после пачки, извлечение текста писем, задачи (название и заметки), встречи (`EventsLoaded`, в
  фоне); `backlinks` — «Где на это сослались» (ушедшие источники убираются); `Links::outside` — наружу ссылка
  канала (`mid:`, `https://…`), иначе `postman://`.
- `mail::MailSource::find`/`resolve`: письмо адреса по подсказке беседы, затем по `Message-ID`, `~<LetterId>` — по
  ключу; `message` — через них.
- `channel::linked`: `link`/`unlink`/`group` (связанные через связанные), `scope` — `беседа:` поиска со связанными,
  `suggest` — та же тема или двое общих людей, само не ставит.
- `channel::person`: `auto` — телефон (без кода страны), почта, ссылка канала ↔ `services`; личные карточки и
  справочник, только база, ручные не трогает; `link` — строка в базе и `SaveContact` со ссылкой в `services` личного
  контакта (у справочника и без ссылки канала — только база); `unlink`; `от:` — все участники одного контакта.
- «Выйти» снимает ссылки сообщений учётки, связи её бесед и её людей.

### в2 — «Переслать в…», «Ответить в…», медиа, экспорт (todo)
- «Переслать в…», «Ответить в…» между каналами; медиа беседы по общей модели и связанным беседам; экспорт ленты.

### Что не сделано (адресно)
- Ссылки `postman://` и `mid:` в HTML письма: IR пропускает только `http`/`https`/`mailto` (`postman_ir::check_link`),
  такие ссылки находятся по тексту, не по адресу ссылки — полоса ir.
- Письма нет в базе — поиск на сервере по `Message-ID` (JMAP `header:Message-ID`, IMAP `SEARCH HEADER`, EWS
  `InternetMessageId`): нужна команда путей — полоса backends.
- `беседа:` писем: документы писем в индексе без адреса беседы — связанная почтовая беседа ищется путём почты.
