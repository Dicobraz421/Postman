> Владелец, 2026-11-14: общие механизмы, хранение, поиск, кросс-ссылки — всё, что возможно, сразу в договор.
> Канал реализует только протокол; всё остальное — ядро, один раз для всех каналов.

## Задача
ADR 0012 «Каналы бесед»: трейт `ChannelPlugin` рядом с `MailPlugin`, общая модель и общие механизмы ядра.
Почта — канал `mail` адаптером поверх `MailPlugin` и `sync::Command`/`Event`; почтовая модель не меняется,
беседа почты = беседа Outlook (`thread`).

### Что делает канал (и только это)
Вход и сессия, синхронизация с курсором, поток событий (Telegram updates, Matrix sync; почта — опрос/IDLE/push),
отправка, правка, удаление, отметки, и перевод своего формата в общую модель и обратно.

### Модель
- **Адреса**: `ChannelId`, `AccountId`, `ConversationId`, `MessageId` — стабильные; адрес сообщения
  `postman://<канал>/<учётка>/<беседа>/<сообщение>` — для ссылок, «Открыть», закладок, командной строки.
- **Беседа**: вид (личная, группа, канал/рассылка, почтовая беседа), участники с ролями, название, аватар, курсор.
- **Сообщение**: автор, время, тело в IR (`crates/ir` — общее представление форматированного текста; канал
  переводит Markdown/HTML/сущности Telegram/Matrix), вложения, ответ на сообщение, цитаты фрагментов, реакции,
  правки (история), удаление, отметки, упоминания; поля канала сверх модели — непрозрачным довеском.
- **Участник ↔ контакт**: участник канала связывается с контактом адресной книги; у контакта несколько адресов
  (почта, Telegram, Matrix) — один человек во всех каналах.
- **Возможности** `ChannelFeatures`: правка, удаление у всех, реакции, «прочитано», «печатает», ответ на сообщение,
  цитаты, упоминания, отложенная отправка на сервере, сквозное шифрование, лимит вложения, длина сообщения.
  Правило «Нет у сервера — нет на экране».

### Общие механизмы ядра
- **Хранение** — единое хранилище ADR 0006: записи сообщений по `MessageId`, тела и вложения по содержимому
  (SHA-256, дедуп со счётчиками ссылок), одна картинка из почты и из Telegram хранится один раз; офлайн-чтение;
  миграции формата, не стирание.
- **Поиск** — один индекс (`crates/search`) на все каналы: тело, автор, участники, имена и текст вложений, ссылки;
  фильтры «канал», «беседа», «от кого»; словоформы, опечатки, раскладка — как у почты.
- **Кросс-ссылки**:
  - ссылка на сообщение любого канала из письма, заметки, задачи, встречи (адрес `postman://…`, при отправке наружу —
    ссылка канала, если есть);
  - «Переслать в…» и «Ответить в…» между каналами: письмо в Telegram, сообщение Telegram письмом, с вложениями
    из хранилища без повторной загрузки;
  - связанные беседы: почтовая беседа ↔ группа Telegram ↔ комната Matrix — видны рядом, «Медиа беседы» и поиск по
    всем связанным;
  - обратные ссылки: у сообщения — где на него сослались.
- **Медиа беседы** (MED-01) — по общей модели, для любого канала и для связанных бесед.
- **Черновики, очередь отправки, отмена отправки, отложенная отправка** — ядро (`send_later.rs`); канал только шлёт.
- **Непрочитанное, счётчики, уведомления**, «заглушить», «закрепить», упоминания меня — ядро, по отметкам канала.
- **Быстрый ответ, ответ на фрагменты, @упоминания** — ядро; канал переводит в свой формат по возможностям.
- **Правила и фильтры** клиента (быстрые фильтры, «упоминания») — по общей модели, не по протоколу.
- **Экспорт и печать** (`crates/export`) — беседа любого канала.
- **Состояние и ошибки**: связь, вход, курсор — общий статус «Проблема → причина → исправление».
- **Секреты** сессии канала — хранилище секретов ОС, как пароли учёток.
- **Включение**: настройка и ключ политики организации на канал (`docs/decisions/2026-11-12-policy-keys.md`).
- **Демо и тесты**: демо-канал (`crates/demo`) с полным набором возможностей — договор проверяется без сети.
