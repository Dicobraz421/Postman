  `IPM.Note.SMIME.MultipartSigned` и одно вложение `multipart/signed` с исходным MIME).

## Итог (2026-11-03)
Сверка с `.msg` самого Outlook (образцы `msg_parser`: `attachment.msg`, `test_email.msg`):
- У вложений не было `PR_RENDERING_POSITION` = −1 — Outlook считал их нарисованными в тексте и не показывал в списке
  (пропавший `отчёт.pdf`, невидимое вложенное письмо). Теперь у каждого вложения: позиция −1, `PR_OBJECT_TYPE` =
  `MAPI_ATTACH`, `PR_ATTACHMENT_HIDDEN`, короткое имя и расширение; у вложенного письма — `PR_ATTACH_METHOD` = 5.
- Картинка, на которую ссылается HTML (`cid:`), — скрытая, `PR_ATTACH_FLAGS` = `ATT_MHTML_REF`: показывается в тексте.
- Письмо с вложениями: `MSGFLAG_HASATTACH` и `PR_HASATTACH`. CLSID — только у корня (у Outlook хранилище вложенного
  письма без CLSID).
- Образцы — настоящие: `tests/data/logo.png`, `report.pdf`; подписанное — настоящая подпись `openssl smime -sign`
  (самоподписанный сертификат `anna@example.test`; было письмо без подписи — отсюда «ошибка вложения»).
- Проверка владельца 2026-11-03: письмо ✅; вложенное открывалось черновиком — у вложенного письма не было
  `PR_MESSAGE_FLAGS` (теперь флаги у каждого письма, по умолчанию «прочитано»); подписанное — всё в теле: в образце
  строки кончались `\r\r\n` (openssl под Windows в текстовом режиме) — образец собран заново, подпись проверяется.
