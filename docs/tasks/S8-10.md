## Сделать
- `migrate::Engine` в потоке ядра: задания из `outbound`, по одной очереди на целевую учётку; шаги письма —
  содержимое есть (иначе `FetchRaw` у источника) → `Import` (или `ServerCopy` пачкой, если `Features::server_copy`)
  → подтверждение (`attach_remote` цели, `place = Synced`) → `Destroy` у источника пачками → снять `detached`.
  Режим `LocalArchive` — шаги «содержимое» (хэш сверен) и «удалить у источника», `place = Local`.
- Режим `Ask` — задание ждёт ответа, но шаг «содержимое» уже идёт (он нужен обоим режимам).
- Пределы: 1–2 одновременных `Import` на учётку; пачки — по `Features` (JMAP `maxObjectsInSet`, EWS ≤ 20);
  `Throttled` — пауза `retry_after`; `TooLarge` — письмо остаётся локальным с пометкой, очередь идёт; `Quota` —
  задание `QuotaFull`; квота — до старта и каждые 500 писем (`settings::Request::Quota` пути, где есть `Feature::Quota`).
- Каждый шаг пишется в `outbound` до и после: после перезапуска задание продолжается с того же шага; повтор
  `Import` после сбоя — сначала проверка по `Message-ID` у цели (пути без `alreadyExists`).
- Отмена: `Cancel { keep_local: false }` — одна транзакция обратно в папку источника (письма без своего
  содержимого — всегда так); `keep_local: true` — оставшиеся в режиме `LocalArchive`.
- Ход — `Event::Migration` не чаще 4 раз в секунду.

## Приёмка
- Тесты на подменном пути (в памяти): выгрузка 1 000 писем; сбой на 400-м и перезапуск — без дублей и потерь;
  `Throttled`, `TooLarge`, `Quota` посередине; пауза и продолжение; отмена в обоих вариантах; удаление у
  источника — только после подтверждения цели.
