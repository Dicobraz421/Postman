> Списки рассылки справочника (T2-41) показывались без состава; в макете — «soc@… 8» и участники в средней колонке.
> Здесь — ядро и пути к серверам; интерфейс «Контактов» — отдельной задачей.

## Сделано
- Ядро: `Command::ExpandList { ticket, address }` → `Event::ListMembers { ticket, address, members, error }`;
  `members: Vec<Principal>` в порядке сервера, вложенный список — участник с `kind == "group"` (не раскрыт);
  `error: Option<ListError>` — `Unsupported` (путь или сервер состав не отдаёт) или `Failed(текст для журнала)`.
- Exchange: `Client::expand_dl` (`ExpandDL` по адресу списка) и разбор `DLExpansion` — имя, адрес (без `SMTP:`),
  признак списка (`PublicDL`, `PrivateDL`); запись без адреса пропускается. Плагин: `ExpandList` → `ListMembers`;
  отказ сервера — `Failed`, без областей (календарь не подключился) — `Unsupported`.
- JMAP: `Client::group_members` — `members` группы `Principal` (список идентификаторов или множество `id → true`),
  участники — `Principal/get` в том же порядке; свойства нет или группы по адресу нет — `Unsupported`.
- Тесты: разбор `ExpandDL` (`crates/ews`, корпус `expand_dl*.xml`), разбор `members` (`crates/jmap`), подменный
  сервер EWS — `list_members_by_expand_dl` (состав, один запрос, отказ сервера).

## Интерфейсу
- Спросить: `Command::ExpandList { ticket, address }`, `address` — адрес списка (`Principal::email` записи с
  `kind == "group"`); ответ — всегда один `Event::ListMembers` с тем же `ticket` и `address`.
- «N участников» — `members.len()` при `error == None`; список — `members` (`display_name()`, `email`), пометка
  «список» — `kind == "group"`. `error == Some(ListError::Unsupported)` — показывать список без состава и счётчика;
  `Failed` — строка «не удалось загрузить» (текст ошибки — только в журнал).

## Не сделано
- Интерфейс «Контактов» (число участников в строке, состав в средней колонке) — другая ветка правит `contacts.rs`.
- Число участников без раскрытия: ни `ResolveNames`/`FindPeople`, ни `Principal` его не отдают — счётчик в строке
  списка появится после `ExpandList` (спрашивать по видимым строкам или при выборе — решение интерфейса).
- Раскрытие вложенных списков вглубь — по задаче один уровень.
- CardDAV, IMAP, LDAP, демо: списков справочника у них нет, `ExpandList` они не обрабатывают (ответа не будет).
- Боевые серверы: `ExpandDL` на Exchange и `members` на The Post / Stalwart на стенде не проверены; RFC 9670 свойства
  `members` не описывает — у Stalwart ожидается `Unsupported`.
