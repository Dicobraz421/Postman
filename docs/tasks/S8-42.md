Сейчас у внешнего адреса в помощнике планирования — «Внешний адрес — занятость неизвестна»: Stalwart отдаёт занятость
только своих пользователей (JMAP `getAvailability`, CalDAV outbox).

## Сделать
- **Сейчас — имеющиеся механизмы** (решение владельца, `docs/decisions/2026-11-05-external-free-busy.md`); свой протокол
  между установками Postman — позже, при необходимости или росте базы, главный вопрос там — установление доверия.
- **FBURL** (vCard `FBURL`, RFC 6350 §6.9.1; RFC 2739; JSContact `calendars`, вид `freeBusy`) или ссылка, указанная на вкладке встречи
  → `GET` по https (тайм-аут 5 с, предел размера, без перенаправлений на http) → VFREEBUSY разбирает воркер → строка
  участника в помощнике с пометкой источника. Нет FBURL или ошибка — как сейчас, «занятость неизвестна».
- Кэш занятости по адресу на сеанс; запрос — только при открытии помощника, не на каждую букву адреса.

## Приёмка
- Тест на записанном VFREEBUSY (интервалы BUSY, BUSY-TENTATIVE, FREE, часовые пояса); ошибка и тайм-аут — «неизвестна».
- Снимок `assistant` с внешним участником, у которого есть FBURL.

## Итог
- Воркер: `Request::FreeBusy` — VFREEBUSY и события с повторами (опубликованные календари Outlook и Google) → интервалы.
- `postman-dav::fetch_public`: только https с именем сервера, без IP и localhost, 5 с, до 2 МиБ; плагин отдаёт его
  интерфейсу блокирующим вызовом — пригодится S8-44.
- Ссылка: `prefs.calendar.free_busy_links` (указана на вкладке) важнее `FBURL` контакта; `FBURL` — только чтение.
- Кэша на сеанс нет: занятость запрашивается при смене недели или участников, как у сервера.
- Снимок: `meeting-link`. Запрос к настоящему серверу не проверен — `docs/manual-tests/S8-42.md`.
