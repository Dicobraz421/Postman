> Решение владельца 2026-11-14 (`docs/SIZE.md` №9): бюджет `postman.exe` ≤ 70 МиБ сейчас; оптимизация — одной задачей
> перед выпуском 1.0, затем бюджет ~64 МиБ.

## Задача
- `lto = "fat"` только в профиле выпуска (CI job `release`), обычная сборка без изменений.
- `opt-level = "s"` холодным крейтам (декодеры картинок, LDAP, самообновление, экспорт) — по замеру бенча.
- Тестовая обвязка интерфейса (`--screens`, `--bench` и т. п.) — за признаком сборки, не в выпуске (~−0,4 МиБ).
- `panic = "abort"` — **обязательно пересмотреть с владельцем в этой задаче** (владелец 2026-11-14: «обязательно
  вернёмся, компромисс выглядит неплохо»). Компромисс: `abort` только для `postman.exe` (~−20 МиБ, сборка −40 %),
  воркер и просмотрщик — `unwind` (разбор чужих файлов с перехватом паники); разбор S/MIME, который сейчас в
  `postman.exe` под `catch_unwind` (`crates/smime`: `verify`, `envelope`, `crl`, `prepare`, `sign`), — перенести в
  воркер; паника в своих потоках (синхронизация, индекс, сеть) закрывает Postman с записью в журнале и отчётом.
  До согласия владельца решение №1 («оставить `unwind`») в силе.
- Замер до/после, бенч `--bench` не хуже; новый бюджет — строкой в `docs/SIZE.md`.

## Готово
`postman.exe` ≈ 62–63 МиБ в выпуске, бенч не хуже, бюджет опущен до ~64 МиБ решением в `docs/SIZE.md`.
