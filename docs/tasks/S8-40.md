## Сделать
Устранить всё, на что жалуется scanpst (MS-PST, раздел 2.4 и 2.7 — обязательные узлы и столбцы):
- Хранилище: таблица папок приёма (Receive Folder Table), очередь исходящих (Outgoing Queue), очередь обновлений
  папки поиска (nid `0xEC1`), шаблоны таблиц nid `0x6B6`, `0x6D7`, `0x6F8`, HMP.
- Шаблон таблицы получателей nid `0x692`: ключи BTH без перекрытия; обязательные столбцы `0E0F000B`, `3002001F`,
  `3003001F`, `0FFF0102`, `3001001F`, `0C150003`, `300B0102`, `0FF90102`, `0FFE0003`, `39000003`, `3A40000B`,
  `39FF001F`.
- Вложение: `PR_ATTACH_SIZE`; строки таблицы вложений и таблицы содержимого папки совпадают с самими объектами
  (те же свойства и значения).
- Список активности поиска (SAL): запись для папки (nid `0x2223`).
- Тест: каждый пункт выше проверяется чтением файла (`outlook-pst`) — узлы есть, столбцы есть, строки таблиц равны
  свойствам объектов.

## Итог
- Узлы нового файла Outlook (по пустому файлу Outlook и pstsdk Microsoft): таблица папок приёма `0x62B` (класс "" →
  корневая папка), очередь исходящих `0x64C`, шаблоны `0x6B6`/`0x6D7`/`0x6F8`, HMP `0xC01`, пустой узел `0xEC1`.
- SAL `0x201` — NID папки поиска спама `0x2223`; SDO, как у Outlook, пуст.
- Получатели: `LtpRowId` с 1 (ключ 0 в BTH — «keys overlap»), все 12 столбцов шаблона заполнены (one-off EntryID,
  ключи записи и поиска, 7-битное имя, флаги).
- `PR_ATTACH_SIZE` — сумма размеров свойств вложения, `PR_MESSAGE_SIZE` — данные узла письма с поддеревом, `0x6604` —
  сумма вложений (формулы Outlook по PSTFileFormat); строки таблиц равны свойствам объектов.
- Тест `scanpst_requirements` проверяет каждый пункт чтением файла через `outlook-pst`. Проверка scanpst — за владельцем.
