> Ручная проверка 1 (2026-10-28), п. 18: вложение нельзя перетащить в другое приложение.

## Сделать
- `sys/dragdrop.rs` — единственное место `unsafe`, у каждого блока — почему он безопасен. `IDataObject` и
  `IDropSource`, `DoDragDrop` с `DROPEFFECT_COPY`. Форматы:
  - `CFSTR_FILEDESCRIPTORW` + `CFSTR_FILECONTENTS` — виртуальный файл без записи на диск, как у Outlook;
  - запасной `CF_HDROP` — копия во временном каталоге Postman (`%TEMP%`), её удаляют при выходе и при старте.
- Перетаскивание начинается движением с нажатой кнопкой от карточки вложения за порогом `SM_CXDRAG`/`SM_CYDRAG`.
  Данные к этому моменту — уже в кэше. Нет их — начать загрузку, курсор «нельзя», по готовности — тост. UI-поток сеть
  не ждёт.
- Файл с макросами (красный щиток) не перетаскивается, как и не открывается.
- Новые features `windows`/`windows-sys` в `app-gpui/Cargo.toml` — в этой задаче. Если нужны правки корневого
  `Cargo.toml` — до неё PR полосы deps (класс B).

## Приёмка
- Тесты (Windows): `IDataObject` отдаёт оба формата; `GetData(FILECONTENTS)` — байты вложения; временная копия
  удаляется; у файла с макросами нет источника перетаскивания.
- Ручная: перетащить PDF и картинку в Проводник, в Word и в окно браузера (загрузка файла) — файл тот же.
