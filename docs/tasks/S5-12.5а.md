## Итог
- Ядро не знает LDAP (ADR 0004): `postman_core::smime::directory` — трейт `Directory`, `lookup` (свой поток, не
  дольше 5 с, ответ — без повторов, ≤ 64 сертификатов по ≤ 64 КиБ), `remember` (проверенные воркером — в кэш адресата
  с источником `ldap`, прежние из каталога заменяются), `stale` (сутки); `recipient_candidates` пропускает
  устаревшие.
- Плагин `postman-backend-ldap` (L2b, протокол — `ldap3`): контроллер домена — `DsGetDcNameW`, база —
  `defaultNamingContext`; вход Windows — SASL GSSAPI (по `ldap://` с шифрованием Kerberos, по `ldaps://` — TLS с
  проверкой Windows и привязкой к каналу); простой вход — только по `ldaps://`. Поиск по `mail` и
  `proxyAddresses`, атрибут `userCertificate` (и `;binary`).
- Не только AD: база — `defaultNamingContext`, иначе первый раздел `namingContexts` (OpenLDAP); вход без пароля
  (каталог, открытый на чтение) и StartTLS; список каталогов — `docs/SMIME.md` Ф5.
- Тесты — подменный сервер с ответами как у AD, OpenLDAP и 389 DS (rootDSE, ссылки, предел записей, отказ поиска,
  нет связи).
- `userSMIMECertificate` (PKCS#7) — S5-12.5в: сертификаты из него достаёт только воркер.
