> Новая функция расширяет ядро (ADR 0004): выгрузка и перенос между учётками выполняют все пути, у кого они есть.

## Сделать
- `model`: `LetterId`, `FolderId`, `JobId`, `MigrationMode { Ask, Upload, LocalArchive }`, `MigrationState`
  (`Asking`, `Running`, `Paused`, `QuotaFull`, `Done`, `Cancelled`), `ImportError` (`TooLarge`, `Quota`,
  `Throttled { retry_after }`, `Rejected(текст)`), `Features::import` (путь умеет выгрузку) и `Features::server_copy`
  (JMAP `Email/copy` между аккаунтами сессии).
- `sync::Command`: `MoveLetters { ids, to }` (ядро решает: своя учётка — `Move` серверу, другая — задание),
  `FetchRaw { letter }` → `Event::Raw`, `Import { job, letter, folder, keywords, received_at }` → `Event::Imported
  { job, letter, remote } | Event::ImportFailed { job, letter, error }`, `ServerCopy { job, letters, to }`,
  `Migration(Request)` (`Answer(mode)`, `Pause`, `Resume`, `Cancel { keep_local }`) → `Event::Migration { job,
  done, total, bytes, state }`.
- Квота — существующий `settings::Request::Quota` → `Usage` (`Feature::Quota`): сейчас отвечает JMAP, в S8 —
  ещё IMAP (`GETQUOTAROOT`); у EWS — нет (`None`, квота узнаётся по ошибке выгрузки).
- `Command::routes` — по учётке письма (`letter_remote`), а не по префиксу ключа; `Local` — без потока сети.

## Приёмка
- Тесты маршрутов: письмо `Local` — в ядро, письмо учётки `@2` — в её поток, `Import` — в поток цели.
- Сериализация событий (журнал) и `Features` по capabilities JMAP (`Email/copy` — `urn:ietf:params:jmap:mail`).
