## S2-01. Слои с проверкой

| Слой | Крейты | Правило |
|---|---|---|
| L0 | `ir` | без I/O |
| L1 | `jmap`, `cache`, `compose`, `calendar`, `search`, `worker`, `smime` (S5-12); протоколы `imap`, `dav`, `ews` (S7) | без UI-зависимостей |
| L2 | `core` | без UI-зависимостей; без протоколов (ADR 0004) |
| L2b | плагины путей `backend-jmap`, `backend-imap`, `backend-dav`, `backend-ews` (S7-02б, ADR 0004); каталог `backend-ldap` (S5-12 Ф5, протокол — `ldap3`) | `core` и только свой протокол |
| L3 | `app-gpui`; `app` (egui, запасной) | только здесь gpui, egui, winit, rfd; протоколы — только через плагины |
| вне | `demo` | данные для демо и тестов |

Приёмка:
- тест рабочей области по `cargo metadata`: у крейтов L0–L2 нет зависимостей (прямых и транзитивных,
  обычных — без dev) от `gpui*`, `egui*`, `eframe`, `winit`, `rfd`; слой ниже не зависит от слоя выше;
  новый крейт без слоя в таблице теста — ошибка;
- `core` не зависит от `rfd`: «Сохранить как…» и выбор файлов — в слое интерфейса, `core::files`
  принимает уже выбранный путь;
- clippy и тесты зелёные, поведение egui-версии не меняется (сохранение и прикрепление файлов работают).

## S2-02. Реестр команд

Модель — крейт `pets-commands` (без UI): id `область.действие`, хоткеи по умолчанию в записи gpui,
контекст gpui; проверка таблицы (id, сочетания, повторы, конфликты клавиш в одном контексте); ключ
названия Fluent и имя действия gpui выводятся из id (`mail.reply_all` → `cmd-mail-reply-all`,
`mail::ReplyAll`).

В Postman: таблица команд `app-gpui` (почта, вид, поиск, календарь, в том числе ещё не сделанные —
ответ, пересылка, удаление, контакты); привязки клавиш строятся из неё по имени действия. Приёмка: все
хоткеи `app-gpui` — из реестра; тест — каждый хоткей Outlook из `docs/HANDOFF.md` §2a есть в реестре,
таблица без проблем; каждой команде соответствует объявленное действие gpui; `scripts/keys-ru.ps1` —
результат прежний.

## S2-03. «Не падать»

Сделано (2026-10-19): вне тестов было 20 мест (`expect`; оценка «127» в плане считала и тесты) — все
убраны, запрет `clippy::unwrap_used`, `expect_used`, `panic` — `deny` на всю рабочую область
(`[workspace.lints]`); в тестах разрешено (`clippy.toml`, в интеграционных тестах — `#![allow]` в начале файла).

- отравленный мьютекс (поиск, воркер) — продолжаем с данными (`PoisonError::into_inner`); регрессионный тест
  `poisoned_writer_lock_does_not_break_the_index`;
- логические инварианты («создан», «запущен», «зарегистрирован») — переписаны без возможности паники;
- потоки и рантайм `core` не запустились — ошибка в окно (`Event::Error`) или в stderr, приложение работает
  дальше; журнал Windows — S2-06;
- старт приложений (каталог данных, хранилище, окно) — сообщение и выход с кодом 1 (`fatal`), без паники.

Фаззинг — на уровне эффектов команд: `crates/cache/tests/fuzz.rs` — случайные последовательности
«пришли / переместились / удалены / помечены» над хранилищем со сверкой с моделью (счётчики папок, порядок
и окна страниц, строки по id). Команды через gpui без окна не запустить (нужен `test-support` gpui) —
пересмотрено с S2-05 (2026-10-20): фаззинг остаётся на уровне хранилища; видимую сторону покрывают снимки
экранов (`--screens`), gpui `test-support` без окна по-прежнему не используем.

## S2-04. Чек-лист соответствия Outlook

`docs/PARITY.md` генерируется тестом из реестра (как `docs/COMMANDS.md` в Урфине): функция, хоткей, статус
(есть / частично / нет). Тест падает, если файл устарел или доля «есть» уменьшилась.

## S2-05. Снимки экранов без человека

Режим `postman-gpui --screens <каталог>`: демо-ящик, набор экранов (список, письмо, поиск, календарь,
помощник планирования) в PNG через PrintWindow; используется агентами для проверки интерфейса вместо
управления окном нажатиями.

Сделано (2026-10-20): `app-gpui/src/screens.rs` — сцены по очереди, как шаги `drive_bench`: состояние — теми же
методами, что у действий; готовность — по состоянию view (строки папки прочитаны; у первого письма есть `doc` из
воркера; результаты поиска «pipeline» прочитаны; раздел и флаг помощника календаря), затем 3 кадра подряд;
кадры — `request_animation_frame`. Снимок — `app-gpui/src/sys/windows.rs`: PrintWindow (`PW_CLIENTONLY |
PW_RENDERFULLCONTENT`) в 32-битную DIB в фоновом потоке (в потоке окна — повторный вход в оконную процедуру
gpui), BGRA → RGBA, PNG (`png` 0.17). Снимок одного цвета — ошибка, код 1. Ящик — `bench_copy(…, 2000)`,
рабочая копия удаляется (`bench::remove_work_copy`). Не на Windows — ошибка «Windows only».

## S2-06. Базис через pets

Крейты `pets-i18n` (Fluent, локаль ОС, проверка на сырые строки; тексты `.ftl` — в Postman),
`pets-shell` (единственный экземпляр — mutex + named pipe, tracing с дублированием ошибок и падений в
журнал Windows «Приложение»), `pets-ui` (тосты справа сверху без перехвата фокуса, история командой; на
gpui). Пишутся под gpui; код Урфина (egui) — только справочно.

Сделано (2026-10-20):
- тексты экранов (`main.rs`, `calendar.rs`, `ir_view.rs`) — в `app-gpui/i18n/{ru,en}.ftl`; тесты
  `texts_are_consistent` (`pets_i18n::check`) и `no_raw_ui_strings` (`pets_i18n::raw_strings` по `app-gpui/src`);
  `--lang ru|en|auto`; журнал и сообщения разработчику — по-английски;
- `pets-shell`: `init_logging("Postman", "POSTMAN_LOG")`, `fatal` (журнал Windows), единственный экземпляр —
  второй запуск показывает окно первого и тост; замеры (`--bench`) идут отдельно;
- `pets-ui`: тосты — пустой поиск, ошибка разбора письма, ослабленная песочница; история — команда
  `view.notifications` (🔔 в строке состояния), Esc закрывает;
- ручные проверки — `docs/MANUAL-TESTS.md`, разделы 3–6.

## S2-08. Стенд Stalwart

Стенд готов раньше фазы 3 (владелец, 2026-10-20) — проверяем клиент сейчас, на нём и строим фазу 2.
Интеграционные тесты `crates/core/tests/stand.rs` (`--ignored`, окружение `POSTMAN_STAND_*`) — тем же кодом,
что и приложение: сессия, почта, push, приглашение туда и обратно, занятость, контакты. Итог и поведение
сервера — `docs/STALWART.md`.

Сделано (2026-10-20), исправления клиента:
- адреса сессии — на адрес подключения (сервер объявляет внутренний; пароль не уходит на другой хост);

- `destroy_event` (с отменой), `share_calendar` (без шаринга занятость пустая), `principal_by_email`;
  `availability` объявляет `principals:availability`; `mailto:` в адресе участника — в любом регистре;
- ответы на `docs/HANDOFF.md` §4 (п. 1–4), пометки [проверить] сняты.
