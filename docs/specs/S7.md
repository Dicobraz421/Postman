# S7. Второй путь: стандарты и Exchange (on-prem)

Открытые задачи — в `docs/tasks/`.

Решение владельца 2026-10-23 (`S0-decisions.md`): цель — по-прежнему Stalwart по JMAP. Второй путь — стандарты:
IMAP + SMTP + CalDAV (со scheduling, RFC 6638) + CardDAV; он же работает и со Stalwart. На переходный период — ещё
Exchange компании (on-prem) только в том, чего стандартами не достать. Простая рабочая база без надстроек Microsoft;
к особенностям Exchange возвращаемся, только если понадобится.

Архитектура — `docs/adr/0003-standards-and-ews.md` (принят владельцем 2026-10-23) с поправкой
`docs/adr/0004-protocol-plugins.md` (ядро функциональное, протоколы — плагины; принят 2026-10-23). Задача = ветка `s7/NN-кратко` = один PR. Проверка — тесты, снимки `--screens` (светлая и тёмная тема), стенд
Stalwart (JMAP, IMAP, CalDAV, CardDAV), боевой Exchange по EWS (тестовая учётка); руками — владелец по
`docs/manual-tests/<задача>.md`.

## Цели

- Учётная запись «стандарты»: почта (IMAP, SMTP submission), календарь и задачи (CalDAV), приглашения и занятость
  (scheduling RFC 6638, free/busy), контакты (CardDAV). Проверяется на стенде Stalwart.
- Учётная запись Exchange (on-prem, EWS, best effort): почта (чтение и отправка), календарь, ответы на встречи,
  занятость (`GetUserAvailability`), GAL (`FindPeople`, запасной — `ResolveNames`) — всё по EWS. Почта Exchange идёт по EWS, не через
  IMAP/SMTP (решение владельца 2026-10-23 вечер, `S0-decisions.md`): у Exchange компании IMAP4 и приём SMTP от
  клиентов выключены (`docs/EXCHANGE.md`). Сервер по факту — Exchange 2013 CU23 (15.0.1497.46), а не 2016+; EWS тот
  же, «best effort» остаётся. Вход — только Negotiate/NTLM через SSPI; TLS — SChannel Windows.
- Несколько учётных записей в одном окне: Stalwart и Exchange на переходный период работают рядом.
- JMAP/Stalwart ничего не теряет: поведение и тесты стенда — как до S7.

## Вне сессии

- У Exchange: правила Outlook, главный список категорий, флаг Outlook для сроков, отложенная доставка, автоответ
  (OOF), задачи, общие ящики и делегаты, особенности S/MIME, streaming-уведомления, OAuth. (Почта Exchange — по
  EWS, в сессии; путь «почта Exchange — его IMAP/SMTP» снят решением владельца 2026-10-23 вечер.)
- CalDAV и CardDAV у Exchange — их нет в Exchange Server (2016, 2019, SE) [факт]; шлюзы (DavMail) — не наш путь.
- У стандартов: ManageSieve (правила, автоответ), OAuth2 (XOAUTH2), общие папки IMAP.
- Exchange Online / Microsoft 365, MAPI, ActiveSync.

## Несколько учётных записей — в существующем дизайне

Новых экранов и приёмов нет: другие серверы ложатся в то, что уже есть (`docs/DESIGN.md`, решение владельца
2026-10-23).

- **Дерево папок:** каждая учётная запись — группа в дереве, как общие ящики сейчас (S4-06, S5-28); метка «без
  связи» — у группы, как метка у аккаунта сейчас. Текущая учётка — та, чья папка выбрана.
- **«От кого»** в композере выбирает учётную запись: поле «От» (S4-06, S5-06б) перечисляет адреса всех учёток;
  письмо уходит путём этой учётки (JMAP, SMTP Stalwart, SMTP Exchange), черновик и копия — в её папки. По умолчанию —
  учётка текущей папки; ответ — с учётки, куда пришло письмо (как ответ из общего ящика сейчас).
- **Календарь:** календари всех учёток — в одном календаре, списком слева с флажками и цветами владельца, как
  «Календари коллег» (S5-22); у своих календарей других учёток подпись — адрес учётки. Встреча, которая есть в двух
  учётках (одно приглашение), показывается один раз — как встреча, где я тоже участник.
- **Поиск** — один на все учётки: «Где искать: Все папки» охватывает папки всех учёток; «Входящие» — входящие текущей
  учётки; результаты — одним списком по дате, у письма — его папка, как сейчас.
- **Настройки** учётных записей — в существующей вкладке «Настройки», раздел «Аккаунты» (добавление в 3 шага на
  месте; вид сервера определяется по адресу: JMAP `.well-known/jmap`, Autodiscover Exchange, SRV для IMAP, SMTP,
  CalDAV, CardDAV — RFC 6186, 6764; не нашёлся — поля адресов серверов на том же шаге).
- **Встреча** (решение владельца 2026-10-23): во вкладке встречи — то же поле «От», что в композере; по умолчанию —
  учётка календаря, выбранного слева, иначе первая в дереве; «Помощник планирования» берёт занятость путём этой
  учётки.
- **Контакты и подсказки адресов** — из всех учёток вместе (личные книги — списком, как «Мои контакты»; справочник —
  у той учётки, где он есть). **Задачи** — списки задач всех учёток, где задачи есть, вместе; новая задача — в
  учётку текущего списка.

## «Нет у сервера — нет на экране»

Одно правило для всех функций, без отдельных задач. У учётной записи — `Features` (ADR 0003): какие области и
функции дал её сервер. Чего нет:
- панели, разделы и кнопки этой функции у учётки не показываются (раздел «Справочник», «Правила», «Автоответ»,
  «Задачи», категории…); при нескольких учётках — по текущей;
- в палитре команд такой команды нет (недоступных строк у палитры нет — новый приём не вводим);
- хоткей такой команды ничего не делает, кроме тоста «Нет у сервера этой учётной записи» (Fluent, один текст);
- открыт модуль, которого у сервера нет, — экран возвращается в «Почту»;
- локальные функции клиента (сроки, «Ждём», «Напомнит», «Исчезнет») работают, если сервер хранит ключевые слова
  (`PERMANENTFLAGS \*` у IMAP); нет — скрыты, как остальное.

| Функция | Stalwart (JMAP) | Стандарты | Exchange |
|---|---|---|---|
| Почта, беседы, поиск, вложения | есть | есть (беседы — клиентом) | есть (IMAP) |
| Метки, категории, сроки, «Ждём» | есть | если сервер хранит ключевые слова | если хранит [проверить в S7-06б] |
| «Отменить» отправку | сервер (FUTURERELEASE) | клиент держит 10 с | клиент держит 10 с |
| «Отправить позже» | сервер | — | — |
| Календарь, встречи, ответы | есть | CalDAV + scheduling | EWS |
| Занятость, «Помощник планирования» | есть | RFC 6638 free/busy | EWS |
| Задачи, поручения | есть | CalDAV VTODO, iTIP | — |
| Контакты | есть | CardDAV | — |
| Справочник, подсказки из GAL | есть | — (подсказки — личные контакты) | EWS `FindPeople` (запасной — `ResolveNames`) |
| Правила, автоответ, квота, общие ящики | есть | — | — |
| S/MIME | есть (MIME клиента) | есть (MIME клиента) | есть (MIME клиента) |

## Проверка на боевом Exchange

Стенда Exchange нет (решение владельца 2026-10-23): тесты — на боевом Exchange компании, «в разумных пределах».

- **Только тестовые учётки** (вопрос 1 закрыт — учётки выданы 2026-10-23); чужие ящики — только для чтения
  занятости. Почта Exchange — по EWS; `POSTMAN_EXCH_IMAP`/`POSTMAN_EXCH_SMTP` нужны только разведке `probe`
  (по умолчанию вход IMAP/SMTP не трогает: `POSTMAN_PROBE_MAIL=1`).
- **Без массовых операций:** запросы последовательно, не чаще 5 в секунду, пачки — до 20 объектов; `ErrorServerBusy`
  — пауза `BackOffMilliseconds`, не больше 2 повторов, затем тест падает с понятным текстом.
- **Уборка после каждого теста:** созданное — с меткой в теме `[postman-test <id прогона>]`, страж удаляет его и при
  падении теста; `cleanup_leftovers` — забытое по метке, только в тестовых ящиках.
- **Письма и приглашения — только между тестовыми учётками:** `test_recipient()` пропускает лишь адреса из окружения,
  любой другой — паника до отправки.
- **Ничего общего для организации:** настройки меняются только у тестовых учёток; прав администратора и командлетов
  Exchange у тестов нет.
- **GAL и занятость коллег — только чтение:** `FindPeople` или `ResolveNames` по конкретной строке (до 20 результатов),
  `GetUserAvailability` — до 3 адресов на окно до недели.
- **Секреты и адрес сервера** — только из локального окружения или файла владельца вне репозитория (значений в
  репозитории нет нигде):

  | Переменная | Что |
  |---|---|
  | `POSTMAN_EWS_URL` | адрес EWS (`https://…/EWS/Exchange.asmx`); нет — Autodiscover по адресу учётки |
  | `POSTMAN_EWS_EMAIL` | адрес первой тестовой учётки — для Autodiscover и как участник, если вход — не адрес |
  | `POSTMAN_EWS_USER`, `POSTMAN_EWS_PASSWORD` | вход первой тестовой учётки: `user@domain` (UPN) или `DOMAIN\user`, пароль |
  | `POSTMAN_EWS_USER2`, `POSTMAN_EWS_PASSWORD2`, `POSTMAN_EWS_EMAIL2` | вторая тестовая учётка (встречи user1 → user2); нет — тест встреч падает с понятным текстом, остальные идут |
  | `POSTMAN_EXCH_IMAP`, `POSTMAN_EXCH_SMTP` | IMAP и SMTP Exchange (`host:port`) — S7-06б |

  Тесты входят только паролем тестовой учётки: Negotiate без пароля (учётная запись Windows) — это ящик владельца,
  его тесты не трогают. В журнал, вывод тестов и PR не попадают ни адрес, ни домен, ни имена: тесты печатают только
  счётчики и коды, `tracing` скрывает адреса, id и тела.
- **Тесты — `#[ignore]` и по окружению**, как у Stalwart; CI их не запускает. Крейт (S7-06а):
  `cargo test -p postman-ews --test stand -- --ignored --test-threads=1` — `sign_in`, `autodiscover`,
  `wrong_password`, `ews_event_round_trip`, `ews_recurring_series`, `ews_meeting_cycle`, `ews_availability`,
  `ews_resolve_names`, `ews_find_people`. Учётка Exchange (S7-06б, плагин `postman-backend-ews`): `crates/backend-ews/tests/stand_exchange.rs`, запуск —
  `cargo test -p postman-backend-ews --test stand_exchange -- --ignored --test-threads=1`; S7-07, S7-08 — ещё
  `exchange_meeting_cycle`, `exchange_series_invite`, `exchange_recurring_in_week`, `exchange_directory_fields`.
- **Корпус ответов** `crates/ews/tests/fixtures/*.xml` — обезличенный (домен → `example.test`); тест
