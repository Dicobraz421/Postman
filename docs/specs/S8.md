# S8. К 1.0: единое хранилище, экспорт, просмотр форматов

Открытые задачи — в `docs/tasks/` (карточки `S8-*.md`, таблица — `docs/tasks/README.md`).

Требования владельца 2026-10-28 — `docs/decisions/2026-10-28-v1-requirements.md`: (1) почта в одной базе, перенос
между ящиками и учётками — правка метаданных одной транзакцией, затем фоновая выгрузка на сервер с отменой и
вопросом «на сервер / локальным архивом»; (2) экспорт в форматы популярных клиентов; (3) просмотр xlsx, pptx и
других форматов, новые — без перекомпиляции.

Архитектура: ADR 0006 «Единое хранилище» (`docs/adr/0006-single-store.md`), ADR 0007 «Просмотрщики форматов»
(`docs/adr/0007-format-viewers.md`); экспорт — раздел ниже. Процесс — скилл `pets-dev`: карточка = задача, волна =
карточки одной полосы (`lanes.toml`) = один PR; класс B — пути `CODEOWNERS` (`crates/worker`, `core/src/backend`,
`core/src/model.rs`, `layers.rs`, `docs/adr`, `Cargo.toml`, `lanes.toml`, `.github`).

## Цели

- **Единое хранилище** (ADR 0006): письмо — строка метаданных с постоянным `LetterId`; тело и вложения — по
  хэшу, один раз на профиль; членство в папках — изменяемое поле. Перенос 100 000 писем между учётками — одна
  транзакция за секунды (замер — ADR 0006 п. 3: 1,4–2,4 с).
- **Локальные папки** «На этом компьютере» — ящики и архивы без сервера.
- **Выгрузка после переноса** — очередь по целевой учётке: продолжается после перезапуска, пауза и отмена, ход,
  пределы и квоты серверов, удаление у источника только после подтверждения.
- **Миграция** кэша формата 5 без повторной загрузки; хранилище больше не одноразовое.
- **Экспорт**: EML, mbox (Thunderbird, Apple Mail), Maildir, MSG (Outlook); PST — пробой и решение по итогу.
- **Просмотр**: xlsx, pptx, ODF, rtf, csv/tsv, md, eml/msg во вложении, bmp/ico/tiff — встроенно; новые форматы —
  модулями WASM в песочнице без перекомпиляции (ADR 0007).
- Бюджеты `docs/HANDOFF.md` §2c не ухудшаются: первый кадр, память, CPU в простое; размер — `postman.exe` ≤ 53,
  воркер ≤ 11 МиБ (решение 2026-10-26), `postman-viewer.exe` ≤ 2 МиБ (новый).

## Вне сессии

- Импорт mbox, EML, PST в Postman (вопрос №7).
- Своё шифрование базы (вопрос №2): в 1.0 — как сейчас плюс предупреждение о BitLocker.
- Перенос календаря, контактов и задач между учётками — только почта.
- Сетевой архив Exchange, общие папки IMAP, делегированные ящики Exchange как цель переноса.
- Синхронизация локальных папок между компьютерами, резервная копия базы (вынос — экспортом).
- Старые двоичные `.doc`, `.xls`, `.ppt` в просмотре (только проверка на макросы), `.7z`, `.rar`, SVG, HEIC.
- Модули просмотра, исполняющие код вне песочницы, внешние конвертеры (ADR 0007, вариант C — отклонён).

## Покрытие возможностей серверов: выгрузка и перенос

Пути — ADR 0004 (плагины). «Используется» — уже в коде, «S8» — делается в этой сессии, «не нужно» — с причиной.

| Возможность | JMAP (Stalwart) | IMAP | EWS (Exchange 2013 CU23) |
|---|---|---|---|
| Письмо целиком с сервера (для базы и экспорта) | блоб `Email.blobId` по `downloadUrl` — используется (S/MIME); S8 — для каждого тела (вопрос №3) | `UID FETCH BODY.PEEK[]` — используется | `GetItem` `MimeContent` — используется |
| Выгрузка письма в папку | `uploadUrl` + `Email/import` (RFC 8621 §4.8) — используется для черновиков; S8 — любая папка, `keywords`, `receivedAt` | `APPEND` (RFC 9051) — используется («Отправленные»); S8 — с флагами и `INTERNALDATE` | `CreateItem` `MimeContent` `SaveOnly` — используется (черновик); S8 — в `SavedItemFolderId`, `PR_MESSAGE_FLAGS` без «черновика», `PR_MESSAGE_DELIVERY_TIME` [проверить на 2013] |
| id нового письма | `created` ответа — используется | `UIDPLUS` `APPENDUID` (RFC 4315) — S8; без него — `UID SEARCH HEADER Message-ID` | `ItemId` ответа — используется |
| Перенос между аккаунтами сервера без выгрузки | `Email/copy` + `onSuccessDestroyOriginal` (RFC 8621 §4.7) — S8 (общие ящики, учётки одной сессии) | нет (разные входы) — выгрузка | `MoveItem` в чужой ящик — не нужно (делегаты вне S7) |
| Перенос внутри учётки | `Email/set` `mailboxIds` — используется | `MOVE` (RFC 6851), без него `COPY` + `\Deleted` — используется | `MoveItem` — используется |
| Удаление у источника | `Email/set` `destroy` — используется | `\Deleted` + `UID EXPUNGE` — используется | `DeleteItem` `HardDelete` — используется |
| Предел размера письма | `maxSizeUpload` сессии — S8 | `APPENDLIMIT` (RFC 7889) — S8; без него — по ответу `[TOOBIG]` | по ошибке `ErrorMessageSizeExceeded` — S8 |
| Пачки и частота | `maxConcurrentUpload`, `maxCallsInRequest`, `maxObjectsInSet` — S8 | одно письмо на `APPEND`; `MULTIAPPEND` (RFC 3502) — не нужно; `LITERAL+` (RFC 7888) — если есть [проверить в `async-imap`] | до 20 писем в `CreateItem`, ≤ 5 запросов/с, `ErrorServerBusy` + `BackOffMilliseconds` — используется (правила S7) |
| Квота | `Quota/get` (RFC 9425) — используется (строка состояния); S8 — проверка до и во время | `QUOTA` (RFC 9208) `GETQUOTAROOT` — S8 (в S7 — «не нужно») | `ErrorQuotaExceeded` — S8; заранее — [проверить] (свойства квоты корня ящика) |
| Повтор без дублей | `alreadyExists` у `Email/import` — S8 [проверить на Stalwart 1.0] | поиск по `Message-ID` в папке цели — S8 | `FindItem` по `Message-ID` (`InternetMessageId`) [проверить на 2013] — S8 |
| Ключевые слова при выгрузке | `keywords` — все, включая `pm.*` | флаги и ключевые слова при `PERMANENTFLAGS \*` — S8 | `IsRead`, `Flag`; метки Postman (`pm.*`, сроки, «Ждём») Exchange не хранит — теряются, вопрос предупреждает (вопрос №9) |

Экспорт и просмотр — на стороне клиента, возможностей сервера не требуют, кроме загрузки письма целиком (первая
строка таблицы).

## Экспорт

### Форматы и что есть в Rust (проверено 2026-10-28)

| Формат | Для кого | Готовое на Rust | Решение |
|---|---|---|---|
| EML (RFC 5322, файл на письмо) | Outlook (открывает и классический, и новый), Thunderbird, Apple Mail, любой клиент | не нужно: байты письма как есть | свой, S8-28 |
| mbox (mboxrd) | Thunderbird (файл папки + каталоги `.sbd`), Apple Mail (импорт «Файлы mbox»; свой экспорт — пакет `Имя.mbox/mbox`), mutt, Gmail | крейты есть, но формат — строка `From ` и экранирование `>From ` | свой, S8-28 |
| Maildir (`cur`/`new`/`tmp`, флаги `:2,FRS`) | mutt, Dovecot (выкладка на сервер), KMail, Claws | не нужно | свой, S8-28 |
| MSG (Outlook, MS-OXMSG поверх MS-CFB) | Outlook: открыть, перетащить пачку в папку — импорт без PST | писателя нет: `msg_parser` (MIT) — только чтение; `oxmsg` — JavaScript; спецификации открыты (Open Specification Promise) | свой на `cfb` (MIT, уже в воркере, умеет запись), S8-29 + S8-30 |
| PST (MS-PST) | Outlook «Импорт и экспорт → Файл данных Outlook» | `outlook-pst` 1.2.0 (Microsoft, MIT) — **только чтение**, запись «не реализована»; libpff — LGPL, только чтение; Aspose — проприетарно | свой писатель **нового** файла (без правки существующего) — пробой S8-33а, полный S8-33б; `outlook-pst` — проверка нашего файла в тестах |

**PST — реалистичный план.** Писать новый файл проще, чем править: последовательно, без транзакций, B-деревья
строятся в конце. Слои: NDB (заголовок Unicode, AMap, деревья узлов и блоков, блоки без шифрования
`NDB_CRYPT_NONE`, CRC), LTP (куча на узле, BTH, контексты свойств и таблиц), Messaging (хранилище, корневая папка,
IPM Subtree, таблицы иерархии и содержимого, письма, получатели, вложения). Оценка — 4–6 тыс. строк, две волны.
Риск — строгость Outlook к обязательным свойствам хранилища и папок. Поэтому сначала пробный файл (одна папка,
одно письмо с вложением): открывает Outlook владельца без «Средства восстановления» — полный писатель; нет — PST
после 1.0, импорт в Outlook — MSG пачкой (вопрос №6).

### Устройство

- **Где что:** байты письма — из `content` базы (ADR 0006); нет — загрузка с сервера (первая строка таблицы
  покрытия), в ходе — счётчиком. EML, mbox, Maildir — обрамление байтов без разбора, в новом крейте L1 `export`
  (без I/O, пишет в `Write`). MSG и PST требуют разбора MIME — разбор в воркере (`MapiMessage`: свойства, получатели,
  вложения, S/MIME — класс `IPM.Note.SMIME*` с письмом вложением), сборка файла — `export`.
- **Охват:** выделенные письма, папка (с подпапками — переключатель), учётка (все папки), всё (все учётки и «На
  этом компьютере»). Дерево папок — деревом файлов: mbox — `Папка` + `Папка.sbd/`, Maildir — каталоги, EML/MSG —
  каталог на папку.
- **Имена:** `ГГГГ-ММ-ДД ЧЧММ — Тема.eml` через `files::safe_name`, повтор — «(2)» (`attach::unique_name`).
- **Ход и отмена:** в строке состояния, как перенос (ADR 0006 п. 5): «Экспорт: 3 120 из 12 480 · Остановить»;
  отмена — готовые файлы остаются целыми, недописанный mbox удаляется; конец — тост «Экспортировано 12 480 писем ·
  Открыть папку».
- **Зашифрованные S/MIME** — как есть (зашифрованными); расшифрованный текст на диск не пишется (решение №4 S/MIME).
- **Место:** каталог — диалог `rfd` (как «Сохранить все»); I/O — в потоке ядра, не в UI.

## Просмотр форматов

ADR 0007: встроенный набор — в воркере (xlsx, pptx, odt/ods/odp, rtf, csv/tsv, md, eml и msg во вложении, bmp/ico/
tiff; PDF уже есть), `Preview::Document` — разделами (листы, слайды). Новые форматы — модули WASM (`wasmi`) в
отдельном процессе-песочнице `postman-viewer.exe`, без импортов, с топливом и пределами; SDK и образец FB2.

## Стенд и проверка

- **Stalwart:** тестовый стенд разбирается, выходит Stalwart 1.0. Тесты стенда S8 пишутся под тот же договор
  окружения (`POSTMAN_STAND_*`, `docs/DEV.md`), помечены `#[ignore]` и прогоняются, когда поднят стенд 1.0;
  находки — в `docs/STALWART.md` и `STALWART-GAPS.md`; поведение, не проверенное на 1.0, — пометкой [проверить на
  1.0]. До стенда — подменные серверы в тестах плагинов (как `crates/backend-ews/tests/mock.rs`).
- **Exchange:** только тестовые учётки, правила S7 («Проверка на боевом Exchange»: последовательно, ≤ 5 запросов/с,
  пачки ≤ 20, уборка); выгрузка — не больше 20 писем на прогон. Тесты — `#[ignore]`, прогон — по карточке.
- **Перенос и экспорт** — тесты на демо-ящике и в памяти (`Cache::open_in_memory`); замер переноса 100 000 —
  `#[ignore]`-бенч в `crates/cache`, release.
- **Интерфейс** — снимками `--screens` (обе темы), руками — `docs/manual-tests/<карточка>.md`.

## Общие правила задач

- Как в S5–S7: цвета — роли темы, тексты — Fluent (оба языка), действия — команды реестра, модальных окон нет.
- Чужие данные — только в воркере (тела, вложения, MIME при экспорте в MSG/PST); песочницу не ослабляем.
- Каждый PR, трогающий `core::sync` или плагины, — с тестами плагинов на подменных серверах; тесты стенда
  Stalwart 1.0 — `#[ignore]` до стенда.
- Перенос, выгрузка и экспорт — в потоках ядра; UI-поток не делает I/O.
- Бюджеты не ухудшаются: `--bench` до и после — в описании PR волн 4, 8, 10, 11; размер exe — одной release-сборкой
  на PR волн 14, 15, 18.

## Решения для владельца

Решено владельцем 2026-10-28 (`docs/decisions/2026-10-28-v1-requirements.md`): все 9 вопросов — по рекомендации;
ADR 0006 и ADR 0007 приняты. Открытых вопросов нет; S8-33б ждёт ручной проверки S8-33а (решение №6).

| № | Вопрос | Решение (по рекомендации) |
|---|---|---|
| 1 | Перенос в другую учётку — удалять ли письма у источника | Да, насовсем — это перенос, не копия: только после подтверждения цели (id или UID) или сверки хэша локальной копии. «Удалённые» источника не используем (квота и дубли при массовом переносе). Копия между учётками — не в S8 |
| 2 | Шифрование базы на диске (с локальными архивами база — единственная копия) | В 1.0 своего шифрования нет: ACL профиля, BitLocker организации, S/MIME — только шифрованными; в «Настройки → Безопасность» — предупреждение, если диск без BitLocker. Своё (ключ под DPAPI, AES-GCM на тела и вложения) — после 1.0 |
| 3 | JMAP: тело письма — из письма целиком (блоб, разбор в воркере) вместо `bodyValues` сервера | Да: одна правда для всех путей, архив и экспорт нужны байты письма, трафик того же порядка; превью строки — по-прежнему от сервера |
| 4 | Модули просмотра: откуда загружать, нужна ли подпись | Обе папки (`%ProgramFiles%\Postman\viewers` и `%LOCALAPPDATA%\…\viewers`), без подписи в 1.0: модуль в двойной песочнице видит только свой файл; у пользовательского — пометка «сторонний» и выключатель. Подпись ключом компании — после 1.0 по запросу |
| 5 | Воркер выйдет за 11 МиБ со встроенными форматами (сейчас 10,35) | Поднять до ≤ 12 МиБ малым шагом, оптимизация — «Перед выпуском» (как решение 2026-10-26); форматы в WASM ради размера не переносим |
| 6 | PST | Пробный файл в S8 (S8-33а); полный писатель — если Outlook владельца открывает пробный без восстановления; иначе PST после 1.0, импорт в Outlook — MSG пачкой |
| 7 | Импорт mbox/EML/PST в «На этом компьютере» | После 1.0 (EML и mbox поверх S8 дёшевы, но не просили) |
| 8 | «Одна транзакция» для очень больших переносов (1 млн писем — 15–25 с) | Пачками по 100 000 писем, каждая — своя транзакция с общим номером задания: список обновляется по ходу, память транзакции ограничена; требование выполняется на пачку |
| 9 | Перенос на Exchange теряет метки Postman (`pm.*`: сроки, «Ждём», «Напомнит»), которых Exchange не хранит | Предупреждать в строке вопроса («Метки Postman на Exchange не сохранятся»); у переноса в «На этом компьютере» и на JMAP/IMAP с ключевыми словами — сохраняются |
