## 2026-10-23 (ночь). Правка и отмена встречи; телефон коллеги у Exchange (S7-07б, S7-08б)

Вопросы S7-07/S7-08 (PR #108). **Правка и отмена своей встречи — да:** в подробностях события, где я организатор, две
кнопки — «Изменить» (открывает существующую вкладку встречи с полями события) и «Отменить встречу» (подтверждение одной
строкой в панели, модальных окон нет). Это новая функция ядра: `Command::UpdateMeeting`, `Command::CancelMeeting` →
`MeetingUpdated`, `MeetingCancelled`; выполняют все пути с календарём — JMAP, CalDAV, EWS. У повторяющейся встречи — по
дизайну, если в нём есть; нет — «Только эту / Всю серию» той же строкой (в дизайне нет — сделано так, вопрос владельцу,
`docs/specs/S7.md`). **Справочник Exchange:** поиск — по-прежнему `FindPeople`; телефон, которого он у Exchange 2013 не
отдаёт, — `ResolveNames` по адресу при открытии карточки человека (`Command::PersonDetails`), без вопроса владельцу.

## 2026-10-23 (вечер). Почта Exchange — по EWS, не через IMAP/SMTP

Разведка боевого Exchange компании (S7-06б, тестовые учётки): Autodiscover POX и вход Negotiate работают, но IMAP4 и
приём SMTP от клиентов на Exchange выключены (почта домена живёт на другой системе). Владелец решил: читать и
отправлять почту Exchange по EWS, сервер не трогать. Путь «почта Exchange — его IMAP/SMTP» (решение 2026-10-23,
вопрос 1) снят. Крейт `ews` получает почту: `SyncFolderHierarchy` (дерево папок), `SyncFolderItems` (письма),
`GetItem` с `MimeContent` (разбор MIME — воркер), `UpdateItem` (прочитано, флаг), `MoveItem`/`DeleteItem`,
`CreateItem` из MIME (`SendAndSaveCopy`, черновик `SaveOnly`), `FindItem` (AQS), `GetAttachment`. Сервер по факту —
Exchange 2013 CU23 (15.0.1497.46), а не 2016+: EWS тот же, «best effort» остаётся. TLS к Exchange — через SChannel
Windows (`native-tls`): его шифры rustls не умеет (S7-06б, `docs/EXCHANGE.md`). Вопрос 1 S7 закрыт.

## 2026-10-23. Ядро функциональное, протоколы — плагины (ADR 0004, S7-02б)

Слова владельца: «ядро функциональное, а протоколы — плагины». `core` — модель, кэш, общий цикл синхронизации,
правило «Нет у сервера — нет на экране» и договор, который путь к серверу выполняет по областям (почта; календарь и
задачи; занятость; контакты; справочник; только у JMAP — правила, автоответ, квота, категории); от протокольных
крейтов `core` не зависит. Каждый протокол — свой плагин поверх своего крейта L1: `postman-backend-jmap`,
`postman-backend-imap`, `postman-backend-dav`, позже `postman-backend-ews`. Интерфейс (композиционный корень)
регистрирует плагины при старте и выбирает путь по учётной записи и области; новый протокол не правит `core`. Поведение
не меняется. ADR 0004 принят; поправка к ADR 0003 (перечисления путей в `core` — не нужны).

## 2026-10-23. Второй путь: стандарты и Exchange (on-prem) — сессия S7

Цель — по-прежнему Stalwart по JMAP. Второй путь — стандарты: IMAP + SMTP + CalDAV (scheduling, free/busy RFC 6638)
+ CardDAV, он же работает и со Stalwart. На переходный период — Exchange компании (on-prem, 2016+ через EWS, best
effort) только в том, чего стандартами не достать: календарь и ответы на встречи, занятость (`GetUserAvailability`),
GAL (`ResolveNames`); вход — Negotiate/NTLM через SSPI; почта Exchange — его IMAP/SMTP. Надстроек Microsoft нет (правила
Outlook, категории, флаги, OOF, задачи, общие ящики, streaming); к ним — только если понадобится. Чего у сервера нет —
не показывается (одно правило, `docs/specs/S7.md`). Несколько учётных записей — в существующем дизайне, без новых
экранов: группа в дереве папок, «От» выбирает учётку, календари всех учёток вместе с цветами владельца (S5-22), один
поиск, «Настройки → Аккаунты»; во вкладке встречи — поле «От» композера, по умолчанию — учётка календаря,
выбранного слева (ответы владельца на вопросы 2 и 3 S7). Заменяет решение 2026-10-20 №5 (IMAP/SMTP — бэклог).

Стенда Exchange не будет: проверка — на боевом Exchange «в разумных пределах», по правилам `docs/specs/S7.md` «Проверка
на боевом Exchange» (только тестовые учётки, без массовых операций, уборка после теста, письма только между тестовыми
учётками, настройки — только у тестовых учёток, GAL и занятость коллег — только чтение; адрес сервера и секреты —
только в локальном окружении владельца, тесты `#[ignore]` по переменным окружения). Стандарты — на стенде Stalwart.
Архитектура — ADR 0003 (модульное ядро: нейтральная модель и адаптеры) — принят. Открыт вопрос 1 S7: тестовые учётки
и включены ли на Exchange IMAP4 и SMTP-приём от клиентов.

## 2026-10-22. Поручения: «Забрать» и «Удалить» — с «Отменить»; «Ждём» — без «Готово, на проверку» (S6-11)

- «Забрать» и «Удалить поручение» — по макету «Поручил я»: сразу, тост «Отменить», без строки подтверждения. Письмо
  отмены (CANCEL) уходит через 10 с — тем же механизмом, что окно «Отменить» у отправки письма; «Отменить» в эти 10 с —
  ничего не отправлено.
- Быстрый фильтр «Ждём» — по макету: мои невыполненные поручения, кроме «Готово, на проверку» (оно ждёт моего решения,
  а не исполнителя); после приёмки результата — тоже нет.

## 2026-10-22. Цвета: ответы владельца по S5-31 (#67)

Тёмная тема: точка графита #CDCDCD, серого #5C5C5C — ΔE2000 ≥ 25 ко всем цветам без исключений. Выделенная строка списка — нейтральное «выбранное» (#EBEBEB, тёмная
#3A3A3A) с полосой акцента слева; синяя #DFF0FF — только метки и кнопки. Категорий — пять цветов; шестую при занятых
цветах не добавить (строка в редакторе), новые цвета — позже через дизайн. «Ждёт ответа» в календаре — пунктирный
контур без заливки, как в `DESIGN.md`. Розовый бренда — и у «Тендеров» (исключение ΔE к красному безопасности).
