# MAC-05. Корпоративное на Mac — Exchange, LDAP, S/MIME

Статус: ⏳

MacBook Air M1 (macOS 13+) и Windows вне домена, корпоративная сеть (или VPN) с Active Directory, корпоративный ящик
Exchange владельца. Сборка — артефакт CI PR (macOS — «macOS» → `Postman-macos-arm64`, как скачать и снять карантин —
`docs/manual-tests/MAC-01.md`, шаги 1–2; Windows — «CI»). Запуск — из Finder или Dock. Журнал — «Настройки» →
«Общие» → «Открыть папку журнала».

## Вход с паролем (NTLMv2 на Rust, обе ОС)

1. Мастер входа: адрес почты → «Найдены настройки: Exchange (EWS)». Поле «Имя пользователя (если отличается от
   адреса)» — пусто, пароль — от ящика → «Проверить и подключить». Ожидается: «Проверка» — подключение и авторизация
   успешно, письма загрузились. Если UPN в AD — не адрес почты, вход всё равно проходит: Postman сам пробует
   `ДОМЕН\имя` (одна лишняя попытка).
2. Не прошло — «Назад», в «Имя пользователя» — `ДОМЕН\имя`, как в Outlook в браузере → «Проверить и подключить».
   Ожидается: вход, письма; адрес ящика в заголовке — почтовый, не `ДОМЕН\имя`.
3. Неверный пароль. Ожидается: «Вход не выполнен: … credentials rejected (offered: …; used: NTLM; TLS channel binding:
   …; tries: …)» и строка «Проверьте пароль или укажите имя пользователя в формате DOMAIN\user». Текст в скобках —
   без логина и пароля, его можно прислать.
4. Cmd+Q (Windows — выход из трея), снова открыть. Ожидается: вход без вопросов, одна попытка (в журнале с
   `POSTMAN_LOG=debug` — нет `ews sign-in rejected`).
5. Календарь и «Справочник» той же учётки работают (вход у областей — тем же логином).

## Вход без пароля (MacBook Air M1)

Mac в домене AD (вход учётной записью домена) или с билетом Kerberos (расширение Kerberos SSO компании или
`kinit имя@ДОМЕН` в Терминале). Проверка билета — `klist` в Терминале: строка `Principal: имя@ДОМЕН`.

6. Мастер входа: адрес почты → «Найдены настройки: Exchange (EWS)». Ожидается: выбор «Войти учётной записью домена
   (без пароля)»; при выборе логин подставлен — `имя@домен` из билета. «Проверить и подключить» — вход без пароля,
   письма загрузились.
7. Перезапуск (Cmd+Q, снова открыть). Ожидается: вход без вопросов. Календарь и «Справочник» работают.
8. Без билета (`kdestroy` в Терминале, перезапуск Postman) — выбора «без пароля» нет; вход с паролем — как в шагах 1–3.
9. Не вошло без пароля — «Не удалось войти учётной записью домена — введите пароль»; прислать текст ошибки и вывод
   `klist` (без пароля).

## Каталог LDAP: поиск сертификата

Нужен билет Kerberos доменной учётной записи. Mac в домене — билет есть после входа в систему; иначе — «Программа
просмотра билетов» (Ticket Viewer) → «Добавить удостоверение» или в Терминале `kinit <имя>@<ДОМЕН>`. Проверка:
`klist` — строка `krbtgt/<ДОМЕН>@<ДОМЕН>`. В каталоге у коллеги-адресата опубликован сертификат S/MIME (в Outlook для
Windows: «Файл → Параметры → Центр управления безопасностью → Электронная почта → Опубликовать в глобальном списке
адресов»).

1. Контроллер домена. «Настройки» → «Безопасность» → «Каталог сертификатов», поле «Сервер» пустое. Ожидается: подсказка «Пусто —
   контроллер домена этого компьютера: `<dc>.<домен>`» (имя из DNS, `_ldap._tcp.dc._msdcs.<домен>`). Сверить в
   Терминале: `dig +short SRV _ldap._tcp.dc._msdcs.<домен>` — тот же узел среди ответов. Сравнить с Windows в том же
   домене — контроллер может быть другим (Windows выбирает по сайту AD), это нормально.
2. Без билета — «нет домена». `kdestroy -A`, закрыть и снова открыть «Настройки» → «Безопасность». Ожидается:
   «Компьютер не в домене — укажите сервер каталога.». В журнале — `no Kerberos credentials`. Снова `kinit`, вернуться
   к шагу 1 (подсказка — снова контроллер).
3. Тексты. Вход: «Домен | Имя и пароль | Без входа»; подсказка входа — «Учётная запись домена (Kerberos), без
   пароля»; StartTLS — «Сертификат сервера проверяет система». При «Имя и пароль» — «Пароль
   хранится в системном хранилище паролей» (на Mac — Связка ключей). Нигде нет «Windows». То же на английском
   («Настройки» → «Общие» → «Язык»).
4. Вход Kerberos по `ldap://` (слой шифрования). Вход «Домен», сервер пустой, StartTLS выключен → «Проверить».
   Ожидается: «Каталог отвечает: сертификатов вашего адреса — N» (N = 0 — тоже успех входа). Ошибки
   `GSSAPI bind failed` и `no suitable GSSAPI security layer` — провал. `klist` — появился билет `ldap/<dc>.<домен>`.
5. Вход Kerberos по TLS. Включить StartTLS → «Проверить» — как в шаге 4. Затем сервер `ldaps://<dc>.<домен>`,
   StartTLS выключен → «Проверить» — как в шаге 4. Если на контроллере включена обязательная привязка к каналу
   (`LdapEnforceChannelBinding = 2`), успех здесь проверяет и её; ошибка `80090346` — провал привязки.
6. Поиск в письме. Новое письмо коллеге с опубликованным сертификатом (начало раздела) → «Конфиденциально» (шифрование). Ожидается: адресат без
   предупреждения «нет сертификата», письмо уходит зашифрованным; у коллеги в Outlook для Windows открывается.
7. Чужой сервер и пароль. Вход «Имя и пароль», сервер `ldaps://<dc>.<домен>`, имя `user@<домен>`, пароль → Enter →
   «Проверить». Ожидается: как в шаге 4; пароль — в «Связке ключей» (поиск `Postman`). Затем «Без входа» на сервере,
   который не пускает анонимно, — понятная ошибка, Postman не падает.
8. Без сети. Отключить Wi-Fi → «Проверить». Ожидается: ошибка примерно через 5 секунд, Postman не падает.
