# MAC-05. Корпоративный ящик на Mac: Exchange (EWS)

Статус: ⏳

MacBook Air M1 (macOS 13+) и Windows вне домена, корпоративный ящик Exchange владельца. Сборка — артефакт CI PR
(macOS — «macOS» → `Postman-macos-arm64`, как скачать и снять карантин — `docs/manual-tests/MAC-01.md`, шаги 1–2;
Windows — «CI»). Запуск — из Finder или Dock.

## Вход с паролем (NTLMv2 на Rust, обе ОС)

1. Мастер входа: адрес почты → «Найдены настройки: Exchange (EWS)». Поле «Имя пользователя (если отличается от
   адреса)» — пусто, пароль — от ящика → «Проверить и подключить». Ожидается: «Проверка» — подключение и авторизация
   успешно, письма загрузились. Если UPN в AD — не адрес почты, вход всё равно проходит: Postman сам пробует
   `ДОМЕН\имя` (одна лишняя попытка).
2. Не прошло — «Назад», в «Имя пользователя» — `ДОМЕН\имя`, как в Outlook в браузере → «Проверить и подключить».
   Ожидается: вход, письма; адрес ящика в заголовке — почтовый, не `ДОМЕН\имя`.
3. Неверный пароль. Ожидается: «Вход не выполнен: … credentials rejected (offered: …; used: NTLM; TLS channel binding:
   …; tries: …)» и строка «Проверьте пароль или укажите имя пользователя в формате DOMAIN\user». Текст в скобках —
   без логина и пароля, его можно прислать.
4. Cmd+Q (Windows — выход из трея), снова открыть. Ожидается: вход без вопросов, одна попытка (в журнале с
   `POSTMAN_LOG=debug` — нет `ews sign-in rejected`).
5. Календарь и «Справочник» той же учётки работают (вход у областей — тем же логином).

## S/MIME

Нужен компьютер с Outlook для Windows (тот же или второй корпоративный ящик); у обоих ящиков — сертификаты S/MIME
корпоративного CA. Снимки экрана на Mac — ⇧⌘4, пробел, щелчок по окну; для шагов 2 и 5 — ещё снимок письма в Outlook.

1. Сертификат в Связке ключей. На Mac — «Связка ключей» → связка «вход» → «Мои сертификаты»: есть свой сертификат
   S/MIME с ключом (треугольник раскрывает закрытый ключ). Нет — импортировать `.p12` из корпоративного CA (двойной
   щелчок по файлу, связка «вход»). Корень корпоративного CA — в «Системе» или «вход» и доверен (профиль MDM или
   «Всегда доверять» для S/MIME).
2. Подписанное с Mac → Outlook. В Postman — новое письмо (⌘N) адресату в Outlook, «Подписать», отправить. Если macOS
   спросит доступ к ключу — «Разрешить» (один раз: «Всегда разрешать»). Ожидается: в Outlook на Windows письмо с
   значком подписи, «Подпись верна», подписант — свой адрес.
3. Подписанное из Outlook → Mac. В Outlook — подписанное письмо на свой адрес Mac. В Postman: значок «Подпись верна»,
   в карточке подписи — корпоративный CA с меткой «корпоративный» (если корень ставит MDM), строка «Отзыв» —
   «не отозван» или «не проверен» (CA без OCSP/CRL по HTTP).
   Корень ставит MDM, а метки «корпоративный» нет — записать в отчёт (решение 2026-11-12 «macos-smime», п. 3:
   тогда корень задаётся отпечатком в `POSTMAN_CORPORATE_CA`).
4. Зашифрованное из Outlook → Mac. В Outlook — «Зашифровать» (и «Подписать») письмо на свой адрес Mac (сертификат
   адресата Outlook берёт из GAL или прошлого подписанного письма из шага 2). В Postman: письмо открывается,
   текст и вложения читаются; если ключ спрашивает пароль — строка «Ввести» в области чтения, после ввода текст
   виден. Перезапустить Postman, открыть письмо снова — открывается (вложения без второго запроса в сеансе).
   Есть смарт-карта с сертификатом S/MIME (по желанию) — то же с картой: без карты — «Смарт-карта не вставлена»,
   с картой — «Ввести» и окно PIN системы; письмо открывается.
5. Зашифрованное с Mac → Outlook. В Postman — письмо адресату в Outlook, «Конфиденциально» (сертификат адресата —
   из шага 3 или «Найти в каталоге»), отправить. Ожидается: в Outlook письмо расшифровывается; в «Отправленных»
   Postman письмо тоже открывается (копия себе).
6. Отказы. В «Связке ключей» корню корпоративного CA временно выставить «Никогда не доверять» → в Postman письмо из
   шага 3 (открыть заново): «Сертификат в списке недоверенных системы». Вернуть «Использовать
   системные настройки». Письмо, зашифрованное не на ваш сертификат: «зашифровано не для вас» с издателем и номером.
7. Тексты. «Настройки» → «Учётные записи» → карточка «Безопасность» и «Безопасность» → «Проверка отзыва
   сертификатов»: «проверяет система», без названия ОС.
