# LOG-01. Системный журнал: ошибки, предупреждения и сведения по уровням

Статус: ⏳

Release-сборка из ветки PR или main после слияния; учётная запись уже добавлена (любая: IMAP, JMAP, Exchange).
Журнал смотреть в «Просмотр событий → Журналы Windows → Приложение», фильтр «Фильтр текущего журнала → Источники
событий: Postman». Правило уровней — `pets-shell/LOGGING.md` в репозитории pets: ошибка — то, чего человек ждал, не
случилось; предупреждение — справились запасным путём; сведения — редкие вехи.

1. «Настройки → Общие → Уровень журнала» — «Сведения», перезапустить Postman. Ожидание: подсказка под настройкой
   говорит, что ошибки, предупреждения и сведения пишутся и в системный журнал. В «Приложении» — новые записи
   источника Postman уровня «Сведения» с кодом 1004, среди них `sync: start, server …` — только имя сервера, без
   адреса почты и пути.
2. Выключить сеть (Wi-Fi или кабель) на минуту, затем включить. Ожидание: запись «Предупреждение» с кодом 1003
   `sync: server unreachable, retrying`; после включения сети почта синхронизируется сама.
3. Ошибка синхронизации: в веб-интерфейсе почты сменить пароль (или отозвать пароль приложения), в Postman —
   «Отправить и получить» (F9) или подождать проверки. Ожидание: запись «Ошибка» с кодом 1001
   `sync: sync failed …` и причиной от сервера; Postman просит пароль заново. Вернуть пароль.
4. Уровень — «Ошибки», перезапустить Postman, повторить шаги 2 и 3. Ожидание: новых записей «Сведения» и
   «Предупреждение» от Postman нет, запись «Ошибка» (1001) из шага 3 — есть.
5. Открыть несколько записей Postman за проверку. Ожидание: ни в одной нет адресов почты, тем и текстов писем,
   паролей; одна строка вида `цель: что случилось — почему` и поля `имя=значение`.
6. Уровень — «Отладка», перезапустить, поработать минуту (открыть письма, папки). Ожидание: в файле журнала
   («Открыть папку журнала») — строки DEBUG; в «Приложении» отладочных записей нет, только «Ошибка»,
   «Предупреждение», «Сведения». Вернуть уровень, который был.
