# S5-12.5: сертификаты адресатов из каталога (AD, OpenLDAP, ALD Pro)

Статус: 🤖 частично (2026-11-06): шаги 2, 4–8 — стенд сети (https, OpenLDAP), шаг 1 — при указанном сервере (подсказка про контроллер домена не проверена); не покрыто — 3 (автопоиск при «Отправить» в домене, открытие в Outlook — владельцу); в шаге 5 для недоверенного сертификата текст «В каталоге сертификата нет» неточен (находка F16)

Стенд — только тестовые учётные записи и тестовый CA; сертификат адресата опубликован в `userCertificate`.

1. Компьютер в домене AD, «Настройки → Безопасность → Каталог сертификатов»: подсказка у пустого сервера —
   «контроллер домена этого компьютера: <имя DC>». «Проверить» — «Каталог отвечает: сертификатов вашего адреса — N».
2. Новое письмо, метка «Конфиденциально», адресат без сертификата в кэше: в «Перед отправкой» — «Нет сертификата» и
   действия «Убрать их · Найти в каталоге · Снять „Конфиденциально“». «Найти в каталоге» — «Ищу сертификаты в
   каталоге…», затем замечание пропадает, у адресата — замок.
3. То же без нажатия: «Отправить» — каталог спрашивается сам (один раз за сеанс на адрес), после поиска «Отправить»
   ещё раз — письмо уходит зашифрованным (в Outlook адресата открывается).
4. Адресата нет в каталоге — «В каталоге сертификата нет…»; сеть выключена — «Каталог недоступен…» не позже чем через
   5 с, окно не замирает.
5. Сертификат из каталога выпущен недоверенным CA — замок не появляется (воркер не принял), в замечании — «Сертификат в каталоге не принят…», а не «В каталоге сертификата нет…».
6. Вне домена: сервер `ldaps://<сервер OpenLDAP или ALD Pro>`, вход «Имя и пароль», пароль — Enter: подсказка
   «Сохранён в Диспетчере учётных данных», в Диспетчере — запись `Postman:ldap:<сервер>`. «Проверить» — отвечает.
7. Вход «Имя и пароль» с `ldap://` без StartTLS — «Каталог недоступен» (пароль по открытому каналу не уходит);
   со StartTLS — отвечает.
8. Вход «Без входа» к OpenLDAP, открытому на чтение: база пустая — берётся из `namingContexts`, сертификат находится.
