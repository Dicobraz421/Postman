# LIN-05. Корпоративное на Linux — Exchange, LDAP, S/MIME

Статус: ⏳ (стенда с Linux и доменом пока нет; интерфейс — LIN-05b)

Linux (GNOME или KDE) в сети с Active Directory: `realm join` (SSSD) или `kinit имя@ДОМЕН`. Билет — `klist`: строка
`Default principal: имя@ДОМЕН`. Журнал — `POSTMAN_LOG=debug`.

## Exchange

1. Вход с паролем (мастер, EWS) — как `docs/manual-tests/MAC-05.md`, шаги 1–5. Ожидается: то же поведение.
2. С билетом Kerberos — «Войти учётной записью домена» (после LIN-05b). Ожидается: вход без пароля, в журнале
   `debug` нет `ews: gss` с ошибкой.
3. `kdestroy`, повторить шаг 2. Ожидается: «Вход не выполнен» с причиной, без зависания и падения.

## Каталог LDAP

4. С билетом: «Безопасность» → каталог — сервер пуст (контроллер найден по DNS), вход «учётной записью». Сертификат
   адресата находится («Конфиденциально» доступно).
5. `kdestroy`, повторить. Ожидается: строка «Kerberos (GSSAPI) login failed — no valid domain ticket? …» в итоге
   поиска, остальное работает.

## S/MIME

6. Свой сертификат — файл `.p12`/`.pfx` (экспорт из Windows «AES256-SHA256» и «TripleDES-SHA1», OpenSSL `-legacy`):
   добавить, ввести пароль. Ожидается: сертификат в списке; неверный пароль — строкой «неверный пароль».
7. Подписанное письмо коллеги из Outlook — «подпись действительна», корпоративный корень (добавлен администратором в
   `/usr/local/share/ca-certificates`) — метка «корпоративный».
8. Отправить себе и коллеге «Подписать» + «Конфиденциально». Ожидается: коллега в Outlook видит подпись и читает; своё
   письмо в «Отправленных» открывается.
9. Перезапуск Postman: ключи снова открыты без вопросов (пароль — из хранилища паролей системы).
