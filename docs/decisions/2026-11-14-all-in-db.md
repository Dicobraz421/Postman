# Всё, что можно, — в базу профиля

Владелец, 2026-11-14: «Все что можно в бд». Продолжение правила 2026-10-28 «почта в клиенте лежит в одной базе»
(ADR 0006): данные Postman на этом компьютере — в одном файле redb профиля (`account-<логин>-<хэш>.redb`). Прежняя
причина держать часть данных файлами рядом — «кэш пересоздаётся при смене формата» — отпала с формата 6: формат
меняется только миграцией.

## Правило

В базе профиля — всё, что Postman хранит сам, **кроме исключений ниже**. Новое хранимое — сразу в базу (таблица
`local` хранилища, `postman_core::local`); файл рядом с базой — только исключением с причиной в этом решении.

## Что переносится

| Было (файл) | Стало (база профиля) |
|---|---|
| `<база>.labels.json` — таблица категорий (копия серверной, `labels::LocalFile`) | `local["labels"]` |
| `<база>.settings.json` — подписи, шаблоны, профиль учётки (`prefs::AccountPrefs`) | `local["account"]` |
| `<база>.settings.images\` — картинки подписей | части хранилища содержимого по SHA-256 (как вложения писем) |
| `subscriptions\<id>.ics` и `.etag` — скачанные подписки на календари | `local["ics/<ссылка>"]`: ETag; файл — частью по хэшу |
| `notices.jsonl` — история уведомлений за 7 дней | `local["notice/<время>/<номер>"]` |
| `smime-intermediates.bin` — промежуточные сертификаты из писем (macOS, Linux) | `local["smime/intermediates"]` |

`categories.json` (`postman_core::categories`) — не локальный файл: это файл таблицы категорий **на сервере**
(JMAP FileNode `.postman/categories.json`), его локальная копия — `labels` выше.

Файлы общей папки данных (история уведомлений, подписки, промежуточные сертификаты) попадают в базу профиля, который
откроется первым после обновления. У другого основного входа (своя база) история начинается заново, подписки
скачиваются заново, промежуточные копятся снова — потерь нет: это кэш и журнал за неделю.

## Исключения — остаются файлами

| Что | Где | Почему не в базе |
|---|---|---|
| Список учёток и вход: `account.json`, `accounts.json` | папка данных | Нужны до открытия базы: из них выбирается, какой файл базы открыть. Пароли — в хранилище ОС |
| Общие настройки `settings.json` | папка данных | Нужны до базы: уровень журнала — до первой строки журнала (а журнал должен записать сбой открытия базы), язык, тема и плотность — до первого кадра, а база может открываться долго (перенос формата идёт в фоне, окно его не ждёт, ADR 0006 п. 6). Экран входа работает без профиля. Настройки — пользователя, не профиля: смена основного входа (другая база) не сбрасывает тему и клавиши |
| Политики организации | реестр, профиль конфигурации, `/etc/postman/policies.json` | Их пишет администратор или ОС; Postman только читает |
| Экспорт писем, архив диагностики, экспорт сочетаний клавиш, сохранённые вложения | куда выбрал пользователь | Пользователь сам сохраняет файл, чтобы взять его с собой |
| Модули просмотра (`*.wasm` + `*.json`) | папки модулей | Их кладёт администратор (или пользователь из настроек) как файлы программы |
| Журнал | папка журнала | Должен пережить сбой базы и рассказать о нём |
| Временные копии вложений: открыть во внешней программе, перетащить в другую программу | `open\`, временная папка | Внешняя программа читает только файл по пути; копии убираются |
| Индекс поиска `<база>.search` | рядом с базой | Свой формат tantivy (сегменты, отображение в память); собирается заново из базы (ADR 0006 п. 7) |
| Значок уведомлений `postman.ico`, автозапуск (Linux `.desktop`) | папка данных, папки ОС | ОС берёт их по пути к файлу |
| Признак переносной установки, файлы обновления | папка программы | Нужны установщику и обновлению вне работы программы |
| Временные файлы переноса формата (`*.redb.v6`, `*.redb.v5.bak`, `*.bak` этого переноса) | рядом с базой | Сами — переходное состояние базы, живут до следующего удачного запуска |
| Данные замера, демо и снимков (`testdata`, `demo.redb`) | папка тестовых данных | Не данные пользователя |

## Перенос

- **Когда.** При открытии базы профиля новой версией, в потоке открытия (не в потоке интерфейса), после переноса
  формата.
- **Как.** Прочитать все старые файлы, записать в базу **одной транзакцией** вместе с отметкой «перенесено»
  (`meta.local_import`); ключ, уже записанный в базу, не перезаписывается. Затем файлы переименовываются в `*.bak`
  (папки — тоже). При следующем удачном открытии базы (отметка есть) `*.bak` удаляются — как `*.redb.v5.bak`
  (ADR 0006 «Перенос формата»).
- **Сбой.** Транзакция не прошла — файлы не тронуты, отметки нет: перенос повторится при следующем запуске, причина —
  в журнал. Испорченный или слишком новый файл не останавливает перенос остального: он не переносится и остаётся
  на месте с причиной в журнале.
- **Формат базы не повышается.** Таблица `local` добавочная: создаётся при открытии, как таблицы задач в формате 5;
  старые таблицы не меняются. Старая версия Postman её не видит: после отката подписи, метки и история — по
  умолчанию (письма на месте), данные остаются в базе и вернутся с новой версией. Картинки и файлы подписок — части
  хранилища содержимого: их вхождения считаются вместе с частями писем (`check_refs`), следующие переносы формата
  обязаны их сохранить.
