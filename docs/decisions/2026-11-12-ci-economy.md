# Экономия CI

Владелец, 2026-11-12: «нахера запускать CI для документов? … нельзя несколько правок одним CI прогонять? давай
оптимизируем».

- **Черновик PR не собирается.** `ci.yml` и `macos.yml` пропускают draft-PR; CI идёт на `ready_for_review` и на каждый
  пуш после него. Агенты открывают PR черновиком, пушат промежуточное без CI и переводят в «готов» один раз — после
  локальных проверок.
- **На пуш в main не собираются комплекты выпуска** (`release` в `ci.yml`, `bundle` со снимками в `macos.yml`): они
  нужны только на теге `v*`, вручную и в PR, что правят сам выпуск. На main остаются тесты — страховка, пока нет
  очереди слияния.
- **Документы** — как и раньше: PR только с `docs/` и `*.md` сборку не запускает (`changes` → `rust=false`,
  `macos.yml` — `paths-ignore`), идёт лишь короткий `gate` на ubuntu.
- **Дальше — очередь слияния (merge queue)** с группировкой: несколько готовых PR проверяются одним прогоном, а тесты на
  пуш в main становятся лишними. Включение — настройка репозитория, по решению владельца.
