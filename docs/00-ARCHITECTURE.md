# Postman — устройство

Корпоративный клиент почты, календаря и контактов под **Stalwart** по **JMAP**. Чистый Rust, рендер на GPU,
Windows и macOS. Приложение семейства «Pets»: общий архитектурный базис — скилл `pets-architecture`
(эталон — Урфин). Всё, что отличается от базиса, — только через ADR в `docs/adr/` с решением владельца
и пометкой «⚠ отступление от базиса». Бюджеты — свои, из ТЗ (`docs/HANDOFF.md` §2c), а не из базиса.

Платформы (решения 2026-11-11 «macos» и 2026-11-12 «linux»): Windows — основа; macOS 13+ на Apple Silicon — вторая,
со своим CI (`macos.yml`) и выпуском (`.dmg`, `.zip`); Linux — третья, tier 2 (карточки LIN-01…; выпуск `.AppImage`, `.deb`,
`.rpm` x86_64 с 0.1.0-beta.6; самообновление — AppImage, у deb и rpm — ссылка «Скачать»).
Код вне платформенных модулей (`sys`) от ОС не зависит.

## Слои

| Слой | Крейты | Правило |
|---|---|---|
| L0 | `ir` | HTML → безопасный IR, без I/O |
| L1 | `jmap`, `imap`, `dav`, `ews` (протоколы), `cache` (redb), `compose`, `calendar`, `search` (tantivy), `worker`, `smime` (CMS и проверка подписи S/MIME, без I/O), `export` (EML, mbox, Maildir, MSG, PST из байтов письма и свойств MAPI; без I/O, кроме `Write`; ни `core`, ни протоколов, ни `worker`) | без UI-зависимостей |
| L2 | `core` (модель, договор путей к серверам и общий цикл синхронизации, рендер через воркер, адресная книга, приглашения, замеры) | без UI-зависимостей; **без протоколов** (ADR 0004) |
| L2b | плагины путей: `backend-jmap`, `backend-imap`, `backend-dav`, `backend-ews` (ADR 0004) | `core` и только свой протокол L1; друг от друга не зависят |
| L3 | `app-gpui` — интерфейс, исполняемый файл `postman.exe`; реестр плагинов — `app-gpui/src/plugins.rs` | только здесь gpui, winit, rfd (диалоги); протоколы — только через плагины |
| — | `demo` — синтетический ящик для демо и тестов | без UI; от него зависит только L3 |

Слои проверяет тест `crates/core/tests/layers.rs` (таблица `LAYERS` — источник правды); новый крейт — сначала в
его таблицу. Ядро функционально, протоколы — плагины (ADR 0004): договор — `postman_core::backend` (`MailPlugin`,
`AreaPlugin`, `Registry`), типы — `postman_core::model`; новый протокол — крейт L1 в `PROTOCOL_CRATES`, плагин
`backend-<протокол>` в `PLUGINS` того же теста и строка в `app-gpui/src/plugins.rs`; `core` не меняется.
Полосы работы по слоям — `lanes.toml`.

## Песочница

`worker` — отдельный процесс-песочница для разбора чужих данных (HTML, картинки, .ics, просмотр вложений: PDF,
ZIP, макросы Office, подпись S/MIME — `postman-smime`). Windows: AppContainer + Job Object + mitigation policies,
запуск без консоли (`DETACHED_PROCESS`); без AppContainer не запускается — письмо текстом (SBX-02). macOS: Seatbelt
`deny default` в самом процессе, пределы памяти, файлов и времени (ADR 0009). Linux: namespaces (по режиму) + Landlock +
seccomp (ADR 0010). Чужие данные в UI-процессе не
разбираются никогда; песочницу не ослабляем без диагностики (`docs/DEV.md`) и ADR. Второй исполняемый файл крейта —
`postman-viewer.exe`: хост модулей просмотра WASM (`wasmi`, признак `viewer`), та же песочница, запуск по
требованию (ADR 0007).

### Договор процесса воркера
Одинаков для `postman-worker` и `postman-viewer` на всех ОС; отличие — только с причиной в строке таблицы.

| | Windows | macOS | Linux |
|---|---|---|---|
| stdin | канал: кадры запросов | то же | то же |
| stdout | канал: кадры ответов | то же | то же |
| stderr | канал к клиенту (хэндл только на запись) | канал | канал |
| Журнал | клиент читает stderr в фоне, строки — в журнал приложения с префиксом `worker: `; ≤ 2048 байт строка, ≤ 100 строк/с, сверх — одна строка WARN | то же | то же |
| Окружение, каталог | только системные пути, `C:\` | пустое, `/` | пустое, `/` |
| Аргументы | — (память — Job Object) | `--memory=…` | `--memory=…`, `--namespaces=optional\|required` |
| Память | частная выделенная память: воркер 1 ГиБ, хост модулей 512 МиБ; исход — «превышен предел памяти» на всех ОС (по строке std об отказе в памяти или коду 6). Windows — commit, Job Object | счётчик кучи `Limited`, выход 6: ядерного предела частной памяти нет (ADR 0009) | `RLIMIT_DATA`; `RLIMIT_AS` — потолок ×2, не меньше 4 ГиБ |
| Время | сторож в процессе, выход 5 | то же | то же |
| Смерть клиента | Job Object `KILL_ON_JOB_CLOSE` | сторож: сменился родитель — выход ≤ 250 мс | то же |
| Уровень для UI | по первому ответу: «песочница: …» — «нет изоляции» с причиной | то же | то же |
| Файлы | AppContainer без прав | Seatbelt, `RLIMIT_FSIZE = 0` | Landlock, seccomp, `RLIMIT_FSIZE = 0` |
| Отказ песочницы | частичная изоляция с причиной (`fallback`) — нет AppContainer у exe вне Program Files | ответ «песочница: …», выход 3 | ответ «песочница: …», выход 3 |
| Запрещённый вызов | ошибка вызова | ошибка вызова | seccomp убивает, `SIGSYS` (159) |
| Код выхода для клиента | код или NTSTATUS | код или 128 + сигнал | код или 128 + сигнал |

Подробно — ADR 0009 (macOS), 0010 (Linux), коды — `exit_name` в `crates/worker/src/lib.rs`.

## Интерфейс

- Патчи gpui — в репозитории `pets`, подключены `[patch]` на ревизию; правки — там, затем поднять `rev` здесь:
  Windows-платформа (`crates/pets-gpui-windows`: шейдеры в exe, кадры по запросу, живой ресайз) и `gpui-base`
  gpui-kit (`crates/pets-gpui-base`: блоки в тексте поля — таблица и картинка в письме, T3-06, T3-07). Связь с macOS —
  крейт `pets-gpui-macos` (не патч).
  Патчи gpui держим минимальными, предлагаем upstream (Zed, longbridge), на новые версии переносим.
- Части интерфейса (ADR 0005): часть (вложения, задачи, контакты, S/MIME…) — модуль с описью `PART` (`part.rs`):
  свои тексты, команды, обработчики `on_action`, сцены `--screens` и сброс своего состояния между сценами. Новая
  часть — `mod x;` в `main.rs` и строка `x::PART,` в `app-gpui/src/parts.rs`; центральные `main.rs`, `commands.rs`,
  `mailer.rs`, `screens.rs` под фичу не правятся. Порядок `PARTS` — порядок реестра команд и сцен.
- Действия пользователя — команды из реестра (`app-gpui/src/commands.rs` собирает `cmd(…)` описей частей, модель
  `pets-commands`): id `область.действие` → действие gpui `область::Действие` (`actions!` — в модуле части) и хоткеи;
  новая клавиша или действие — только через таблицу команд своей части; название — `cmd-…` в `app-gpui/i18n/{ru,en}/commands.ftl`. Чек-лист соответствия Outlook
  `docs/PARITY.md` генерируется из реестра: `POSTMAN_UPDATE_DOCS=1 cargo test -p postman-gpui parity`.
- Тексты интерфейса — только через Fluent (`pets-i18n`, `tr!`): ключи в `app-gpui/i18n/{ru,en}/<часть>.ftl`
  (файл на часть экрана, список — `TEXTS` в описи части), оба языка; литерал с кириллицей в `app-gpui/src` ловит
  тест `no_raw_ui_strings`, расхождение наборов — `texts_are_consistent`. Журнал (`tracing`) — по-английски.
  Названий ОС в текстах нет (решение 2026-11-12 «no-os-names», тест `texts_have_no_os_names`). Язык — ОС или
  `--lang ru|en`.
- Жизнь процесса — `pets-shell`: журнал (`POSTMAN_LOG` или «Уровень журнала» в настройках; файл в папке журнала,
  на Windows — ещё журнал «Приложение»), самообновление — `pets-update` (`app-gpui/src/update.rs`, T3-12),
  `fatal`, единственный экземпляр (второй запуск показывает окно первого; `--bench` и `--screens` — вне правила).
  Уведомления — тосты `pets-ui` (`Toasts` в `Mailer`), история — 🔔 в строке состояния.
- Экран — набор view со своим состоянием, встроенных через `.cached(...)` с явным размером; изменение —
  `cx.notify()` своего view, связь частей — событиями. Иначе gpui раскладывает всё окно на каждом кадре (S1-06).
- Модальных окон нет: подтверждения — одной строкой в самом окне, уведомления — тостами.

## «Не падать»

Вне тестов нет `unwrap`/`expect`/`panic!` (clippy `deny` на всю рабочую область, `clippy.toml`); ошибка —
`Result`, отравленный мьютекс — `PoisonError::into_inner`, сбой старта — `fatal` (сообщение и выход).
