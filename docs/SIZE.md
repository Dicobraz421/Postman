## Как мерить

```
cargo build --release --workspace                      # как CI и package.ps1
# разбивка кода по крейтам (нужен PDB): cargo install cargo-bloat
set CARGO_TARGET_DIR=target\size                       # опыты — в своём каталоге, не трогая target\release
set CARGO_PROFILE_RELEASE_STRIP=false
set CARGO_PROFILE_RELEASE_DEBUG=1
cargo bloat --release -p postman-gpui --bin postman --crates -n 60
# данные (.rdata) и таблицы раскрутки (.xdata) — по карте компоновщика:
cargo rustc --release -p postman-gpui --bin postman -- -C link-arg=/MAP:postman.map
```

`cargo bloat` считает только `.text` и по именам символов (обобщённый код gpui, встроенный в наш, он относит к gpui
или `std`); карта `/MAP` делит по объектным файлам (встроенное — к нашему крейту). Числа — оценка, до ±5 %.
`strip` и `debug` на exe под MSVC не влияют (отладка — в PDB): exe с ними и без — одного размера.

### Почему рост

- **19 МиБ — сборка mingw (кросс из Linux)**, не MSVC. Тот же спайк в MSVC — **23,05 МиБ**: 4 МиБ разницы — тулчейн,
  а не код.
- Рост 23,05 → 36,9 МиБ (+13,85) — **функции приложения**, которых в спайке не было (там — список, чтение и календарь
  на демо-данных): синхронизация с сервером (сеть и TLS +4,0), полнотекстовый поиск (+3,2), весь остальной интерфейс —
  окно письма, ответ, встречи, контакты, правила, автоответ, общие ящики, вложения, беседы (+5,4), тексты EN/RU и
  журнал (+0,4), сборка писем (+0,3). Сам gpui не вырос.
- Сверху всего — **раскрутка паник**: `.xdata` + `.pdata` = 4,7 МиБ и площадки очистки в коде. С `panic = "abort"` exe
  — 25,8 МиБ (−11,1). Это самый крупный рычаг, но он меняет поведение (ниже, решение 1).

**Вывод: рост обоснован** — это функции, которые мы сделали, и TLS/поиск, без которых их нет. Лишнего в нашей
части почти нет; крупные «лишние» куски — внутри gpui (декодеры, второй resvg, Markdown/HTML), их убирает только патч.

### panic = "abort" — что на самом деле меняется

Сейчас (`unwind`) паника **уже** завершает процесс почти везде: обработчик окна gpui (`wndproc`) и фоновые задачи gpui
(колбэки пула потоков Windows) — функции `extern "system"`, раскрутка через них — аварийное завершение. Паника
переживается только в **своих потоках**: синхронизация (`sync`), клиенты воркера (`render`, `extract`), построение
индекса, `cache-flags`, задачи tokio. На это опирается правило S2-03 «не падать» (отравленный мьютекс —
`PoisonError::into_inner`, тест `poisoned_writer_lock_does_not_break_the_index`). С `abort` паника в этих потоках
завершает Postman (журнал и запись в журнал Windows остаются: хук паники срабатывает до завершения), а не тихо
останавливает синхронизацию или индекс. Тесты (`cargo test`) собираются с раскруткой в любом случае. Воркер — отдельный
процесс: для него разницы нет (клиент перезапускает его при любом коде выхода, 0xC0000409 уже расшифрован).

### TLS

aws-lc — криптопровайдер rustls по умолчанию в reqwest 0.13 (1,3 МиБ: код и таблицы кривых). ring даёт тот же набор
TLS 1.2/1.3 (AES-GCM, ChaCha20, X25519/P-256/P-384) и ту же проверку сертификатов (rustls-platform-verifier, хранилище
Windows); теряется ключ X25519MLKEM768 (гибрид с постквантовым: у нас он сейчас предлагается последним, без key share)
и подпись сервера ECDSA P-521. SChannel — TLS самой Windows (политики TLS из GPO, корпоративный CA без посредников),
но это другой стек и другие ошибки. S/MIME (S5-12, `docs/SMIME.md`) aws-lc не нужен: CMS — RustCrypto, закрытые
ключи — CNG Windows; бэкенд подписи для `rustls-webpki` в воркере выбирается там же и с TLS не связан.

## Воркер (`postman-worker.exe`)

4,00 МиБ после (5,19 до): `.text` 1,84, `.rdata` 2,03. Крупное: chrono-tz (база поясов calcard для .ics) 1,16 МиБ данных,

данных, ради которого воркер и существует; обоснован.

**S5-07 (встроенный просмотр вложений): 4,00 → 8,75 МиБ (+4,75).** Почти всё — рендер PDF `hayro` 0.8 (чистый Rust без
`unsafe`, Apache-2.0 OR MIT): интерпретатор и разбор PDF ~0,85, растеризатор `vello_cpu` 0,36, шрифты (`skrifa`,

крейтов hayro (они только в воркере, `Cargo.toml`) было 9,33 МиБ. ZIP-оглавление (`zip`, MIT) — 0,05, составные

## Решения для владельца

| № | Вопрос | Рекомендация | Решение владельца (2026-10-21) |
|---|---|---|---|
| 1 | `panic = "abort"` в release: −11,1 МиБ (36,9 → 25,8) и сборка на 40 % быстрее; паника в своих потоках (синхронизация, индекс, клиенты воркера, tokio) завершает Postman, а не только поток | Да: паника интерфейса и задач gpui уже завершает процесс; лучше честное падение с записью в журнале, чем молча вставшая синхронизация | Оставить `panic = "unwind"` |
| 2 | Криптопровайдер TLS: aws-lc (как есть) / ring (−0,9 МиБ) / SChannel (−2,2 МиБ) | ring: тот же rustls и та же проверка сертификатов, теряются только P-521 и PQ-гибрид; SChannel — если нужны политики TLS из GPO. Проверка — стенд Stalwart (`--live`) | — |
| 3 | `lto = "fat"` (−0,8 МиБ, +40 % ко времени сборки) | Нет для обычной сборки; можно отдельным профилем `dist` только для архива в CI | — |
| 4 | Патчи gpui в `pets` ради размера (декодеры, второй resvg, Markdown/HTML) — до ~2,5 МиБ | Не сейчас: каждый патч — перенос на новые версии gpui; вернуться, если бюджет не сойдётся | — |
| 5 | Бюджет exe | Таблица выше | `postman.exe` ≤ 45 МиБ (2026-10-21); ≤ 48 МиБ (2026-10-22, S0), оптимизация — перед выпуском |
| 6 | Воркер с просмотром PDF (S5-07) — 8,75 МиБ: бюджет ≤ 10 МиБ / PDF без рендера — сведения и текст (~5 МиБ, текст без шрифтов неточен) / рендер PDF отдельным процессом по запросу | Бюджет воркера ≤ 10 МиБ: воркер не грузится при старте Postman (первый кадр не меняется), а страница вместо «откройте в приложении» — основная польза просмотра | Воркер ≤ 10 МиБ; PDF остаётся `hayro` в песочнице |
