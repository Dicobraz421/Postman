Postman — почта, календарь и контакты для Windows 10/11 x64

Файлы:
  postman.exe         — приложение
  postman-worker.exe  — изолированный разбор писем (песочница); всегда рядом с postman.exe
  postman-viewer.exe  — просмотр вложений модулями (песочница); рядом с postman.exe
  install.ps1         — (только в архиве) установка для текущего пользователя, без прав администратора
  postman.portable    — (только в архиве) метка: эта копия обновляется из архива, а не из MSI
  README.txt          — этот файл

Новые версии и отдельные файлы: https://github.com/Dicobraz421/Postman/releases
Пропал postman-worker.exe или postman-viewer.exe — скачайте только его из выпуска своей версии
и положите рядом с postman.exe; переустанавливать не нужно.

УСТАНОВКА

Способ 1 — MSI, для всех пользователей компьютера (нужны права администратора):
  двойной щелчок по postman-<версия>-windows-x64.msi, подтвердить запрос UAC. Postman ставится
  в C:\Program Files\Postman, ярлык «Postman» — в меню «Пуск». Вопросов установка не задаёт.
  То же через winget (когда пакет опубликован):  winget install Pets.Postman
  Тихая установка, например для MDM или групповой политики:
    msiexec /i postman-<версия>-windows-x64.msi /qn
  Другая папка:  msiexec /i postman-<версия>-windows-x64.msi INSTALLDIR="D:\Apps\Postman"
  Обновление — новый MSI поверх (перед ним выйдите из Postman: «Выход» в меню значка в трее); старую версию поверх новой MSI не ставит.
  Удаление — «Параметры» → «Приложения» → Postman → «Удалить» или  msiexec /x <файл .msi> /qn
  В «Приложениях» у бета-версий свой номер: 0.1.0-beta.2 показывается как 0.1.302.

Способ 2 — архив, только для себя, без прав администратора:
1. Распакуйте архив postman-<версия>-windows-x64.zip в любую папку.
2. Откройте в этой папке PowerShell (в Проводнике: Файл → «Открыть Windows PowerShell»
   или правой кнопкой по пустому месту → «Открыть в Терминале») и выполните:

     powershell -ExecutionPolicy Bypass -File .\install.ps1

Postman ставится в %LOCALAPPDATA%\Programs\Postman, ярлык «Postman» — в меню «Пуск».
Сценарий даёт папке установки право чтения для приложений-песочниц (ALL APPLICATION PACKAGES):
без него песочница воркера и просмотра вне Program Files не запускается. Повторный запуск — обновление
(перед ним выйдите из Postman: «Выход» в меню значка в трее; крестик только прячет окно).

Оба способа сразу не нужны: два ярлыка «Postman» в «Пуске». Переходите на MSI — сначала удалите копию
из архива (install.ps1 -Uninstall, см. ниже). Данные и вход у обеих копий общие, они не теряются.

Параметры install.ps1:
  -Destination <папка>   другая папка установки
  -NoShortcut            без ярлыка в «Пуск»
  -Uninstall             удаление: файлы и ярлык (данные и сохранённый вход остаются)
  -RegisterEventSource   по желанию, от администратора: зарегистрировать источник «Postman»
                         журнала Windows «Приложение» (вместе с -Uninstall — снять регистрацию).
                         Без него ошибки в журнал тоже пишутся, но «Просмотр событий» показывает
                         перед текстом «Не найдено описание для события…». MSI регистрирует его сам.

УДАЛЕНИЕ (архив; MSI — см. выше)

  powershell -ExecutionPolicy Bypass -File "%LOCALAPPDATA%\Programs\Postman\install.ps1" -Uninstall

Данные остаются, их можно удалить вручную:
  %LOCALAPPDATA%\Postman — кэш писем, поисковый индекс, демо-ящик;
  «Диспетчер учётных данных» → «Учётные данные Windows» → записи «Postman:…» — сохранённый вход.

ЗАПУСК

Меню «Пуск» → Postman. При первом запуске — строка входа: адрес сервера, имя и пароль; пароль
хранится в диспетчере учётных данных Windows. Забыть вход: postman.exe --sign-out.
Демо без сервера: postman.exe --demo
Параметры: postman.exe --help

Окна консоли у Postman нет. Вывод --help, --bench и снимков (--screens) идёт в консоль, из которой
запущен postman.exe, или в файл (> файл). Командная строка cmd не ждёт окна приложения —
запускайте так: start /wait postman.exe --help. PowerShell: postman.exe --help | Out-Default.

Замер для разработчиков: start /wait postman.exe --demo --bench > bench.txt
(окно само листает список и меняет размер около минуты — не трогайте его).

ЖУРНАЛ

Ошибки и сбои — в журнал Windows «Приложение», источник Postman («Просмотр событий»).
Подробнее — файл журнала %LOCALAPPDATA%\Postman\logs\postman-ДАТА.log (по файлу на день, хранится неделю).
Подробность обоих — «Настройки» → «Общие» → «Уровень журнала» (со следующего запуска); там же «Открыть папку
журнала» и «Отчёт для поддержки» — архив для обращения. Переменная POSTMAN_LOG=debug сильнее настройки.

ОБНОВЛЕНИЕ

Postman сам предложит новую версию тостом «Вышла версия X · Установить». Скачивает он только после
«Установить», проверяет подпись выпуска, закрывается и запускается уже новым. Копия из MSI ставит
новый MSI (Windows спросит разрешение — UAC), копия из архива заменяет свои файлы из нового архива.
Раз в сутки Postman спрашивает у GitHub номер последней версии, без данных о вас. Выключить —
«Настройки» → «Общие» → «Проверять обновления автоматически»; организация — политикой
HKLM\Software\Policies\Pets\Postman, AllowUpdate = 0 (DWORD или строка): тогда запросов нет вовсе.
Канал — там же: «Стабильный» или «Предварительный» (бета-версии).
Версии до 0.1.0-beta.5 обновить себя не умеют: один раз поставьте новую версию вручную (способ 1 или 2).
Бета-тестерам после этого — выбрать канал «Предварительный», иначе следующие беты Postman не предложит.

ПОДПИСЬ

Подписанная сборка — с цифровой подписью на вкладке «Цифровые подписи» в свойствах postman.exe.
Неподписанную при запуске из распакованного архива SmartScreen предупредит:
«Подробнее» → «Выполнить в любом случае». После install.ps1 предупреждения нет: сценарий снимает
с установленных файлов отметку «загружено из Интернета».
Скачанный неподписанный MSI SmartScreen предупредит так же — «Подробнее» → «Выполнить в любом случае».
